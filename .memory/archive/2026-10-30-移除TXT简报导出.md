# 2026-10-30 彻底移除 TXT 简报导出（export）功能

合入 commit：1e209a6（功能）+ `.memory/` 单独提交。委托书式任务。

## 背景

`export`（定时从 `news_summaries` 取过阈值文章生成 TXT 简报写 `outputs/`、推飞书、记 `brief_batches`/`brief_items`）是早期过渡机制，被人工筛选控制台 + 报送存档完整接管后已一个月无人使用。用户以委托书要求**彻底移除**：代码、脚本、控制台接口、数据库表、文档，不留开关与兼容层。删除时线上库有 43 批 / 2929 条简报数据，随表一并删除（用户明确拍板）。

## 删除的文件（10）

`scripts/run_export.ps1`、`scripts/tasks/schedule_export_tasks.ps1`、`src/workers/export_brief.py`、`src/adapters/db_postgres_export.py`、`src/console/exports_routes.py`、`src/console/exports_service.py`、`src/console/exports_schemas.py`、`src/domain/templates.py`（`BriefTemplate`/`DEFAULT_BRIEF_TEMPLATE`，指向的模板文件早已不存在）、`tests/test_export_brief_threshold.py`、`tests/test_export_source_format.py`。

## 关键修改

- CLI/流水线：`_add_export` 子命令、`DEFAULT_PIPELINE`/`STEP_REGISTRY` 的 export 步骤全部移除；`runs_service._ALLOWED_STEPS` 由 `DEFAULT_PIPELINE` 推导，控制台触发随之不再接受 export。dashboard 快照去掉 `latest_export` 字段（该函数本就没有任何调用方，按委托书保留函数本体）。
- 飞书：删 `notify_export_summary` 及仅被它使用的 `_render_message`/`_build_preview`/`_format_counts`/`_upload_file`/`_send_file_message`/`_FILE_URL`；`_MESSAGE_URL`、`_get_token`、`_send_text_message` 等被存活函数共用，保留。`Path`/`Mapping`/`Sequence` 导入随删除清理。
- 回链（`_links.fetch_link_candidate_bodies`）：去掉 `latest_brief` CTE 后正文候选优先级为 `manual_reviews.summary`（lateral 内 `status='exported'` 优先、再 `decided_at`、`updated_at`）→ `nullif(btrim(ns.llm_summary),'')` → `''`。注意保留了 `llm_summary` 的 `nullif(btrim())` 包裹（纯空白摘要要落到 `''`），这是「其余逻辑不变」的一部分。
- `search_drawer_attribution.js` 第 6 行注释删除（归因链上不再提简报初稿）。

## 迁移与 baseline 冲突（本次最重要的经验）

- 新迁移 `20261030120000_drop_brief_tables.sql`：up 先 `drop view if exists public.latest_brief_items`（init 迁移建的视图依赖 brief_items，全新库重放时必须先删）再 drop 两表；down 按 schema.sql 原样重建（两表、主键、唯一约束、FK on delete cascade、三索引、两触发器）。
- **baseline（20241101000000）里有无条件的 `create table if not exists brief 两表`**。schema.sql 还含这两张表时，`test_backfilled_baseline_is_applied_without_changing_existing_schema`（加载 schema.sql → 删 baseline 版本号 → dbmate up → 要求逐字不变）是 no-op；删表刷新后，该测试重放 baseline 会把表**原样建回来**，用例必红。
- **直接删 baseline 建表也不行**：重放链上 `20260729130100_add_brief_items_article_created_at_index` 给 `brief_items(article_id)` 建索引，而 `article_id` 列只存在于 baseline 的老建表里（init 迁移 20250926172450 建的表没有该列），删掉会 `UndefinedColumn`。
- **最终方案（用户拍板「改 baseline 迁移」）**：baseline 的建表改为条件补建——仅当 `brief_batches` 与 `submitted_reports` **都不存在**时执行（远古库才可能缺 brief 表；真实老库本就有 → `to_regclass` 命中跳过；删表后的库有 submitted_reports → 跳过；全新库链上补建 → init no-op → 索引迁移有列可用 → 链末被 drop）。brief 触发器块保留但各加「表存在才建」守卫。
- 同理验证：`test_full_migration_replay_matches_schema_snapshot`（全链重放 vs schema.sql）与 baseline 用例均绿。
