# 用户拍板的约束（「别改回去」清单）

这里记录用户明确拍板过的行为约束。**改动这些地方之前先对照本文件**——很多「优化」是用户明确否决过的，不要好心改回去。相关细节见 `archive/` 对应文件。

## UI 形态

- **存档页全局待确认提示已删除（2026-11-03 拍板）**：曾放在 `.archive-tabs-row` 左侧的「待确认回链 N」链接（`#archive-nav-pending`）不要加回——点开正文后详情标题栏的「待确认回链 N」批量按钮足够明显，顶部再来一份是重复提示。详情标题栏批量按钮是待确认的唯一全局入口；`/api/submission-archive/link-queue` 接口保留（当期批量弹窗仍按 `report_id` 使用）。
- **加分词典页签（2026-10-20 定稿）**：两组分区「加分词在上、减分词在下」，每组末尾有独立添加入口；写入顺序与展示一致（先加分、后减分）；**即时保存**（无「保存加分词典 / 放弃修改」按钮）：值提交或焦点离开整行自动保存、删除立即写库、删最后一条弹确认；完全空白行只作本地草稿、半行/非法值标红并拦住保存；状态行显示保存结果和最后修改；副标题与初始「修改后自动保存」提示已删除；「生效说明」不再解释先加分还是先减分。
- **系统设置页形态（2026-10-20 定稿）**：左栏竖向导航（>1200px 两栏，≤1200px 折叠为顶部等宽页签），「高级」归在「系统」组、不再做右对齐小字入口；顶部页签版已被否决。每个分区有页头（长标题 + 一句话说明），内容按 `.settings-card` 分卡片；短标签/页头文案映射在 `core.js` 的 `SETTINGS_TAB_META`。
- **高级页即时保存（2026-11-11 拍板）**：高级页四个分区（教育关键词、京内关键词、来源别名、自动排序关键词）**删掉「保存X / 放弃修改」**，改为焦点离开整块时校验并写库（与加分词典、筛选页摘要框一致）；同一块里换字段不提交，芯片「×」删除立即提交，添加词仍等失焦（连续录入不逐个发请求）。写不进去（校验失败/409/422/网络错误）时状态行旁出现描边小按钮「还原为已保存内容」（本地快照，不发请求）；409 另给「载入最新配置」。保存成功**不重绘卡片**（保住批量编辑展开与焦点），服务端 trim/去重结果写回控件。分区版本冻结在本编辑器上、只被自己的保存成功推进——页面整体重载换 payload 时不得偷偷升级版本（否则会静默覆盖别处修改、永远不出现 409）。**不要加回保存/放弃按钮，也不要改成防抖/输入即保存。**细节见 [archive/2026-11-11-高级设置即时保存.md](archive/2026-11-11-高级设置即时保存.md)。
- **控制台亮暗主题（2026-11-11 拍板）**：覆盖整个控制台（登录/注册/改密、用户与排班、系统设置、筛选、汇总审阅、值班、报送存档、值班汇总、`admin_entry`）。入口是账号菜单「外观」，管理员和值班编辑都可设置；三档「跟随系统 / 亮色 / 暗色」，偏好只存 `localStorage.console_theme`（缺省/非法按 system），系统主题变化实时跟随，不建数据库字段、不加 API。形态：单行「外观 [跟随系统 ▾]」原生 `<select>`，向值班页「历史班次」下拉框看齐（边框、控件底色、正常白/黑文字，选项不随 hover 变蓝）；面板宽度与账号菜单触发器一致；外观放在修改密码之前，分割线只在退出登录之前。**不要在原生 select 上用 `text-align` / 不对称 padding 强行居中**——2026-11-11 试过两版（`c502382`、`c88c561`），用户认为改得更差并删除这两个提交；要严格居中只能换自定义下拉。登录/注册/改密页没有控件，但遵循已存偏好与系统。亮色模式颜色/布局/间距保持改造前。细节见 [archive/2026-11-11-控制台亮暗主题.md](archive/2026-11-11-控制台亮暗主题.md)。
- **设置页模型步骤表（2026-11-06 委托书拍板，取代同日早间的「模式槽 + 内容槽」形态）**：每行是「接入点下拉 + 模型输入框」两个独立控件，无模式开关列。下拉首项「跟随默认（默认接入点显示名）」；模型留空用所选接入点的 `default_model`，留空灰字提示实际会用的模型。联动：跟随默认下输入模型→当场切默认接入点（用户看得见，不是保存时悄悄改）；换接入点→清空模型；选跟随默认→清空模型（该组合不合法）。**后端契约：模型名与服务商绑定——「无接入点、有模型」校验拒绝，默认模型归各接入点（`llm_endpoints` 必填 `default_model`），`llm_models` 无顶层 `default`**。步骤名必须单行显示，不许出现「摘要生 / 成」式逐字断行。细节见 [archive/2026-11-06-默认模型跟随接入点.md](archive/2026-11-06-默认模型跟随接入点.md)。
- **来源别名留在高级页签、卡片内单列（2026-11-04 拍板）**：不做成单独一栏或独立页面/页签（用户考虑过、明确否决）。卡片内的「后缀 / 别名 / 回退来源」固定**单列纵向**排列，不恢复两栏网格（两栏时回退来源会掉进窄栏折行）；字段标题前的 1/2/3 编号表示处理顺序，同时充当字段边界。细节见 [archive/2026-11-04-来源别名单列布局.md](archive/2026-11-04-来源别名单列布局.md)。

- **值班页页签文案（2026-10-26 拍板）**：值班编辑控制台的「已选结果」页签更名为「审阅」，`data-tab` 仍是 `review`；管理员端的「汇总审阅」文案不动，不要跟着改。
- **审阅页排序模式手机端（2026-11-09 拍板）**：触屏上**只有 ⋮ 手柄能起拖**（44px 命中区 + 按住 120ms 门槛 + 4px 移动阈值），不要再把 `handle` 设成 `undefined` 让整卡可拖——那样手指落在卡片上就进拖拽态，列表滚不动。排序模式工具条在手机上按「退出排序 / 自动排序」+「预览 / 归档」两行排列并**吸顶**，退出入口必须始终可见；移动端排序时标题链接不接管点击（防误跳原文）。跨组拖拽保持原语义：拖进另一个分组会改写该条京内/京外与正负面分类并落库，**不要**改成禁止跨组或加二次确认（用户明确选择保持现状，误拖靠手柄 + 长按门槛规避）。顶部四个桶按钮在手机上的横向滚动是既定设计，不需要改成换行。细节见 [archive/2026-11-09-审阅页排序模式手机端.md](archive/2026-11-09-审阅页排序模式手机端.md)。

## 功能语义

- **接入点主机白名单只能追加、读取路径不做白名单拦截（2026-11-07 委托书拍板）**：最终白名单 = 内置默认列表（8 个服务商域名，见 `src/config.py` 的 `DEFAULT_LLM_ALLOWED_HOSTS`）+ `LLM_ALLOWED_HOSTS` 追加的域名——环境变量**不能**替换或删掉默认列表。读取已保存配置（设置页负载、保存 `llm_models`、流水线 `load_business_config`）只做结构校验；白名单外的接入点在设置页标红展示，由用户在控制台改掉或删除；只有保存 `llm_endpoints` 本身要求全在白名单内；流水线加载按「是否有步骤在用」收窄失败半径（没人用只记警告）。白名单外主机在任何路径都不发请求（传输层 + 探针双道拦截）。
- **env 文件改动自动读取，无手动重载入口（2026-11-07 委托书拍板）**：控制台进程在处理请求前统一检测三个 env 文件的指纹（mtime/大小/存在性），有变化自动重读（无空档：先读全量再覆盖、只删文件里已不存在的变量）。「重新加载环境变量」按钮与 `/api/admin/settings/environment/reload` 已删，**不要加回**；流水线步骤是计划任务新起的进程，**不接入**这套机制（一轮运行中途换 Key 会让同一轮前后行为不一致）。进程启动前导出的变量始终优先于文件值。
- **接入点保存的前端拦截范围不能比后端宽（2026-11-07 委托书拍板）**：只有「后端这次会实测（新增 / 连接信息或默认模型改动 / 刚被设为默认）且 Key 未配置」才拦下不发请求；格式不对必拦（与后端 `LLM_API_KEY_ENV_PATTERN` 同规则）；没改动、也不会被实测的接入点即使没 Key 也只警告不拦——一个暂时没 Key 的旧接入点不允许卡住无关的修改。宁可少拦交给后端 422，不能多拦。

## LLM 错误处理

- **4xx 错误按归属处理，不再逐篇重试/计数（2026-11-06 拍板，2026-11-07 修订）**：`post_chat_completion` 只重试 408/429/5xx 与网络异常；400/401/403/404/409/422/425 只发一次。系统性错误（参数/能力/鉴权/模型名/配置类）不记文章失败、不触发兜底，**也不提前停止、不让整轮报错**；`geo-classify`、`external-filter`、`summarize` 三个步骤都按这个口径处理，每轮最多发一条飞书告警，文章保持原待处理状态，接入点恢复后下一轮自动重试。article 级 4xx 单次计数，geo 达上限保持 `pending_beijing_gate` 作为死信，不得静默按北京放行；临时错误保留原重试/计数/兜底。**不要退回“任何异常都算文章失败、三次后按北京放行”，也不要恢复“系统性错误取消剩余请求 + 停止后续批次 + run 重新抛出”**——请求失败本身没有成本，每轮照常请求才能让接入点恢复后自动跑通，整轮报错还会拖累排在其后的无关步骤。
