# 自动排序关键词入设置页（2026-09-23 交付）

> 状态：已合入 main（merge b0e9ce5）并推送 origin，worktree/分支已删，用户浏览器验收通过。17/17 变异捕获，合并后全量 1254 passed。定稿方案：高级页签三文本块、进 SETTING_SECTIONS、允许类别留空（全空保存确认）、跨类重复报错。

## 背景（排查得来的事实）

- 词表原硬编码在 `review_tab_sort.js` 的 `CATEGORY_RULES`，纯前端：三类别（市教委/中小学/高校）+ 固定兜底「其他」；first-match-wins 优先级 市教委→中小学→高校→其他；对 标题+摘要+来源显示名 小写子串匹配；排序经 `/api/manual_filter/order` 持久化。
- `app_settings.section` 是普通 text 主键、无 CHECK 约束，新增分区不需要 migration。
- `load_business_config` 要求 SETTING_SECTIONS 全部分区在库有行，缺一个整条流水线报 BusinessConfigError——这是「部署必须先 import-settings --apply」的根因。
- manual_filter.html 同时服务管理员和值班编辑，模板→JS 传上下文的现成模式是 `data-workspace-mode`。

## 维护要点

- 词表存在 `app_settings.review_sort_keywords`，由**数据 migration INSERT** 播种（该分区没有旧配置文件，不走 import-settings）。迁移 JSON 与 `REVIEW_SORT_KEYWORD_DEFAULTS` 的一致性由 `test_migration_seed_matches_code_defaults` 锁定，**改默认词表必须新增迁移（不能改历史文件）**。
- 审阅页渲染路径（web_routes._review_sort_rules）：读行→校验→**失败三重回退**默认词表（行缺失/损坏/读库异常都降级并记日志，页面永不被排序词表阻断）；jsdom 测试经 monkeypatch `web_routes.get_adapter` 注入固定词表。
- 词表查重按 toLowerCase（"K12"="k12"）；jsonb 不保对象键序但按键取值无影响；校验器输出键序固定为优先级序。
- 新增 SETTING_SECTIONS 后 test_console_settings_migration 的 fresh_deploy 和 phase2 两条真实 DB 测试都要在隔离库执行新迁移（settings_count 计数、imported_sections 列表同步）——下次再加分区照此办理。
- 「类别顺序被打乱」类变异必须靠 jsdom R4（一词命中两类归高优先级）才能抓到，普通各归各类用例测不出优先级；**回归时别删 R4**。
