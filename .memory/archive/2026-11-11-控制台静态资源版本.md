# 控制台静态资源版本与暗色缓存修复

日期：2026-11-11
合入：`8545a9a`（CSS 链接补版本号）、`f4aa701`（静态资源指纹），合并提交 `278cf6a`；main 上同时有并行的高级设置即时保存提交 `28e0145`、`9d59124`。

## 背景

用户反馈暗色模式下查重弹窗里的 `.archive-item` 仍是亮色卡片，并贴出了实际 DOM：

```html
<section class="archive-item">
  <div class="archive-item-head">... archive-item-badge / date / title / submission-duplicate-item-state ...</div>
  <div class="archive-item-body">...<span class="archive-item-source">（北京日报）</span></div>
</section>
```

排查后发现 `.archive-item` 的代码已经是 token 化的（`background: var(--card-bg)`、文字 `--text-primary`/`--text-secondary`），新建浏览器上下文里渲染是正常的暗色。真正的问题是 `search.css` 的 `<link>` 没有 `?v=` 版本号，浏览器继续使用主题改造前的旧 CSS，旧 `.archive-item` 是白底。

## 根因

浏览器按**完整 URL** 缓存资源，不会因为磁盘上的文件内容变了就主动重新读取。控制台里模块 CSS/JS 大多已有 `?v={{ version }}`，但核心 CSS（variables/base/components/layout/utilities）和 `search.css` 一直没有；这次主题改造改了 `search.css`，旧缓存仍在，于是暗色页面里露出白卡片。

## 改法

1. **补全版本号**：9 个页面模板里所有 stylesheet 链接都加 `?v={{ version }}`，包括 `search.css`。脚本链接原本就全部带版本号。
2. **版本号从时间戳改成静态资源指纹**：`web_routes._asset_version()` 每次渲染时扫描 `web_static` 下所有文件，按 `(相对路径, mtime_ns, size)` 做 sha1 短哈希（12 位）。文件不变时版本稳定，浏览器可以正常缓存；任意 CSS/JS 改动或新增文件后，下一次请求自动换版本号，不需要手动 bump。
3. **测试**：
   - `tests/test_console_theme.py` 新增 `test_stylesheet_links_are_cache_busted`（10 个页面逐一渲染，所有 stylesheet 必须带 `?v=`）；
   - 新增 `tests/test_console_web_assets.py`：文件不变时版本稳定、改动/新增后版本变化、页面实际使用 `_asset_version()`；
   - 更新 `tests/test_console_web_routes.py` 中两条锁死无版本号链接的断言。

## 验证

- 全量 pytest：worktree 与合并后的 main 均 **1939 passed, 0 failed, 0 skipped**。
- 所有模板已无未版本化 stylesheet；脚本链接原本均已版本化。
- `variables.css` 之外仍零颜色字面值，主题契约测试继续通过。

## 决策

- **`?v=` 必须保留**：它是缓存键，不是“浏览器检测代码变化”的机制；删掉会回到依赖浏览器/代理重新验证的状态，这次的旧 `search.css` 就是反例。
- **不做 Jinja `static_url()` helper**（用户 2026-11-11 拍板）：项目小、新增资源频率低，显式链接更直观；用测试兜底比多一层间接更划算。以后资源数量明显变多或需要按文件内容 hash/CDN 时再考虑。
- 版本指纹用 mtime + 大小，不读文件内容：正常保存/部署会更新 mtime；若部署工具保留旧 mtime 且大小巧合不变会漏，属于极端情况。HTML 本身被缓存时仍可能拿到旧链接，需要刷新一次。
- 原生 select 的居中补丁已回退（见 [2026-11-11-控制台亮暗主题.md](2026-11-11-控制台亮暗主题.md)）；本任务不再调整外观样式。
