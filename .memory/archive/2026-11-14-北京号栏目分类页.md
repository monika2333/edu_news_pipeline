# 2026-11-14 北京号栏目分类页（北京日报客户端栏目）

- 日期：2026-11-14
- 提交：`fe4a8af`（直接改 main，单文件级别的小改动）
- 无数据库变更、无新环境变量、无迁移、控制台前端零改动

## 需求与现象

用户要把北京日报客户端的「教育」栏目页加进「设置 → 数据源 → 北京号」：

```
https://static.bjd.com.cn/static/category/?categoryId=6095f818e4b054f0ea85207a&channelId=5b165687a010550e5ddc0e6a&columnId=5ba1f926e4b0976ea0d9a0fc
```

添加时被拒，错误是 `Unable to derive Beijinghao column code from: <URL>`
（`parse_column_code` 只认 `…/bjhrootcolumn/system/<24hex>` 形态）。

## 站点事实（2026-11-14 实测）

- 页面本身是 JS 渲染空壳：`<title>` 为空、稿件列表 `#story-list-*` 全空，数据由
  `window.onload` 里的两个请求拉；`_base` 里 channelId 写死生产频道
  `5b165687a010550e5ddc0e6a`，`jiansuoProxy = //jiansuo.bjd.com.cn`，`siteProxy = //xinwen.bjd.com.cn`。
- 列表（真正的分页接口，页面无限滚动用的就是它）：
  `GET https://jiansuo.bjd.com.cn/cass/search?channelId=<ch>&categoryId=<cat>&page=N`
  —— `page` 从 **0** 起、每页 10 条、按 `publishTime` 倒序；
  `data.content[]` 每项有 `id / title / url / publishTime / storyType / source`；
  `data.totalElements`（该教育栏目 692）、`data.size=10`、`data.totalPages`。
  采 12 页共 120 条：URL 全部在 `xinwen.bjd.com.cn`、`storyType` 全是 `COMPO`、`source` 全是「北京日报客户端」。
- 首屏接口 `GET https://xinwen.bjd.com.cn/columns/<columnId>/category/<categoryId>/pages/0/stories.json`
  按 blocks（置顶/列表）给首屏，但 **`pages/1` 与 `pages/0` 返回同一批**——页号不是分页，
  拿到 `--pages N` 的翻页语义上不能靠它。
- 正文：`GET https://xinwen.bjd.com.cn/content/<id>.json`，信封与北京号
  （`peking.bjd.com.cn/content/<id>.json`）完全同构（`code/data/title/publishTime/url/content`），
  现有 `_parse_detail_payload` + `html_to_markdown` 直接可用；`publishTime` 形如
  `2026-11-13T02:14:25.364+0000`（UTC），`_timestamp_to_iso` 已能解析。
- 账号名：页面 `<title>` 是空串，名称来自页面渲染标题用的
  `GET https://static.bjd.com.cn/mdms-res/category/json/<channelId>/category.json`
  （26 KB，`data[]` = 栏目清单，按 `uuid == columnId` 找到栏目，再按
  `categories[].uuid == categoryId` 取 `name`）。该项目下 `name = 教育`，
  栏目名是「产经新闻（标准）」（不对外，不进显示名）。
- 抽样 4 篇老稿（2026-07 前后）正文 JSON 均 `code=0`、markdown 823–2918 字。

## 设计

- **不新建来源**：挂在 `beijinghao` 下（稿件 source 仍固定「北京日报」，与用户口径一致），
  控制台、`business_config`、迁移全都不动。
- `ColumnEntry` 保持三字段：新形态的 `column_code` 存**规整后的栏目页地址**
  （同 21jingji / chinadaily「账号 = 栏目 URL」的先例），抓取时按 `page_url`
  判型（`parse_category_input()` 命中则走检索接口）。
- 新增 `CategoryEntry`（column_id / category_id / channel_id / page_url）与：
  - `parse_category_input(raw)`：接受完整 URL、协议相对、无协议；`channelId` 缺省补
    `DEFAULT_CHANNEL_ID`；同域名但路径不对或参数缺失/非法 → `ValueError` 中文提示
    （不要再落到无关的“栏目编号”报错上）；参数顺序固定，保证同一栏目任意写法同一标识。
  - `CategoryEntry.search_url(page)` 产出检索接口地址。
  - `_category_search_rows()` / `_parse_category_list_payload()`：信封校验 + 行解析；
    `storyType ∈ {VIDEO, LIVE}` 跳过（无可用文字正文，对应页面「文章」页签口径）。
  - `category_meta_url()` / `parse_category_meta_name()`：账号名解析（纯函数，HTTP 留在
    `account_profiles._request` 里，保住它的重试与 8 秒预算）。
- `normalize_url` / `_is_detail_url` / `_detail_json_url` 改为认 `DETAIL_HOSTS`
  （peking + xinwen），正文 JSON 域名按稿件 URL 自己的域名取。
- `feed_item_to_row`：列表自带精确 `publishTime`（不再只有日期零点）。

## 实现中自己抓到的坑

第一版 `_collect_category_items` 用「过滤 existing_ids 之后为空」当末页判据——
整页都已入库时会提前停、后面页的新稿抓不到（与新京号 2026-11-06 同一个坑）。
改成 `_category_search_rows(payload)` 单独给出**原始行数**，末页只看它；
补了「第 1 页全已入库仍翻到第 2 页」的回归用例。
