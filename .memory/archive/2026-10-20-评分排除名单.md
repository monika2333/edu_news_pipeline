# 评分排除名单（全局黑名单）

日期：2026-10-20。合入：5d44e09（ff-only）。分支 `feature/score-exclusion-keywords`，worktree `D:/2program_practise/edu_news_pipeline_exclusions`。

## 背景

`score_keyword_bonuses` 是加减分词典，范围 −100～100。靠很大的负数既存不进 `numeric(6,3)`，也无法稳定压过正向加分，因此需要一个独立的「命中即淘汰」名单。用户 2026-10-20 拍板做一期（全局关键字排除），并明确不改大负数、不做按报别/来源拆分。

## 语义

- 新分区 `app_settings.score_exclusion_keywords`：有序 JSON 字符串数组，空数组合法（不排除任何文章）。
- 评分工序顺序：**排除名单 > 加分词典 > 阈值跳过（bonus skip）> 模型评分**。
- 标题 / 正文 / 已有关键词任一包含排除词即命中；子串、大小写敏感，与加分词典完全一致。
- 命中：不计算加分、不调用 LLM、`status=filtered_out`、`score=NULL`、`raw_relevance_score=NULL`、`keyword_bonus_score=0`、`matched_rules=[]`、`score_details.excluded_rules`（`rule_id=exclude:<词>`）、`llm_skipped=true`、`skip_reason=keyword_excluded`；不写 `news_summaries`。
- 日志一行拆分：`Skipped N LLM calls: X keyword exclusions, Y bonus below threshold.`
- `pipeline_runs.config_snapshot` 增加该分区（按配置顺序）。
- 设置页不新增页签：加分词典页签内、加分/减分表格下方的独立卡片；多行文本一行一个词，失焦即时保存；重复词带行号报错、空行忽略、空名单合法；与加分词典各自独立版本、脏标记与 409 重载（只重绘自己的挂载点）。

## 设计取舍

- **用 `app_settings` 新分区而不是新表/大负数**：这是全局单值配置，沿用既有分区契约即可获得乐观锁、审计与快照；新表会为一份全局名单引入无谓的 schema 与管理面。大负数受 `numeric(6,3)` 与「可能压不过正向加分」双重限制，不可行。
- **`filtered_out` + `score=NULL` + `score_details.excluded_rules`**：不新增 status 枚举，人工筛选/导出等下游无需感知新状态；`score=NULL` 与 bonus-skip 的「实际净分」明确区分，`skip_reason` 让两条跳过路径可追溯。命中时不计算加分（省一次匹配），所以 `keyword_bonus_score=0` 并不失真。
- **匹配与加分词典一致**：同一套 `_collect_text_sources` 与子串/大小写语义，避免用户面对「同一个词在加分里命中、在排除里不命中」的认知分裂，也让实现与变异测试可复用既有边界。
- **UI 用页签内独立卡片 + 即时保存**：排除名单与加分词典共享同一决策场景（同一批文章、同一页配置），放一起减少跳转；即时保存沿用该页既有交互（无保存/放弃按钮），但分区版本与重载必须独立，否则一个分区的 409 重载会清掉另一个分区的草稿。

## 版本与部署

- 新分区 version 从 1 开始；迁移 `20261020150000_add_score_exclusion_keywords_setting.sql` 用 `ON CONFLICT (section) DO NOTHING` 播种 `[]`，若设置页先写入则保留用户值；down 删除该行。

## API 变化

- `GET /api/admin/settings` 的 `sections` 多一个 `score_exclusion_keywords`（value 为字符串数组、version、updated_at、updated_by）。
- `PUT /api/admin/settings/score_exclusion_keywords`，body `{expected_version, value: string[]}`；成功返回 `{item}`；重复词/空串/非字符串/非数组返回 422；版本过期返回 409。无其他 API 变化。

## 风险与后续

- 子串匹配会误伤：如排除「招聘」会命中「招聘会」正常报道；一期按用户要求保持与加分词典一致的子串语义。
- 名单全局生效，无法按报别/分类/来源差异化；后续若需要，可在新分区或新表上做维度化，不要改这个分区的语义。
- 排除只影响保存后打分的文章，已打分/已入库文章不会重算；需要清理存量时必须单独写脚本。
- 后续可考虑在设置页提示「排除词同时出现在加分词典」的交叉项，一期按委托不做交叉校验。
