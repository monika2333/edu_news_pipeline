# 查重结果弹窗放弃/撤销后保留滚动位置（2026-11-15）

## 背景

用户反馈：控制台「检查重复」打开的「查重结果」弹窗（`#duplicate-review-modal`）里，往下滚动到当前重复组中后部点卡片上的 🗑️「放弃新闻」后，弹窗会自己弹回顶部，得手动再滚回原位置继续看。要求与筛选、审阅页一样「停留在改动位置」。

## 根因

- 弹窗结果区 `#duplicate-review-results` 是唯一的滚动容器（`.modal-body`，`overflow-y: auto`）。
- `review_duplicates_modal.js` 的 `showDuplicateReviewGroup()` 末尾无条件 `results.scrollTop = 0`。
- 这个归零是 2026-07-02「分页展示重复新闻组」（`502f35e`）为**切换重复组**加的，本身合理。
- 2026-07-05「放弃后隐藏条目」（`b6723d7`）为了重算组数/页码/空态，在 `hideDiscardedDuplicateReviewItem()` 与 `restoreDiscardedDuplicateReviewItem()` 里复用了同一个函数，于是「组内删一条」也被顺带回顶部（撤销同理）。批量放弃在循环里调用 hide，表现一样。

对照既有模式：审阅页用 `const scrollY = window.scrollY` … `window.scrollTo({ top: scrollY })`（`review_tab_data.js`）在列表重载后恢复位置；筛选页决定后是就地移除卡片、不重载列表。弹窗缺的就是这层「重排后保留滚动」。

## 用户拍板的范围（2026-11-15）

- **全部放弃路径 + 撤销都保位**：单条 🗑️、下拉选「放弃」、工具栏批量放弃；撤销/失败恢复当前组时也保位。
- **组清空仍自动切下一组**（从顶部开始）——保持现有交互，不改成「留在本组显示空态」。
- 回归测试做 jsdom 行为测试，`/admin/review` 与 `/duty` 双端都跑。

## 实现

`review_duplicates_modal.js`：

- `showDuplicateReviewGroup(index, { preserveScroll = false } = {})`：入口记录 `previousScrollTop`；末尾按选项 `previousScrollTop` / `0`；「一组都不剩」的早退分支显式归零。
- `hideDiscardedDuplicateReviewItem`：`updateDuplicateReviewGroupAfterRemoval` 之后，若组仍有条目则 `preserveScroll: true`；这条是最后一条时组被标空、自动切下一组，切组仍回顶部。
- `restoreDiscardedDuplicateReviewItem`：恢复前记录 `wasActiveGroup = getActiveDuplicateReviewGroup() === group`；原地恢复才保位，从「已被切走的空组」恢复时切回该组并从顶部显示。
- 首次打开、上一组/下一组按钮不传选项，行为不变（回顶部）。

## 维护提醒

- 弹窗结果区是独立滚动容器，不要给「组内增删」路径复用一个「切组就回顶部」的渲染函数；需要重算页码/计数时用 `preserveScroll: true`。
- 不要用源码字符串断言代替这个行为测试——`scrollTop` 在 jsdom 里可读可写，直接断言「放弃后没有归零」才是有效回归。
