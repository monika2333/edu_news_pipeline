# 2026-11-06 默认模型跟随接入点

委托书任务（Wimp 出题）：每个接入点有自己的默认模型；步骤的「接入点」和「模型」分开选，模型留空用所选接入点的默认模型。合入 9a214ee（功能 ecfd6c9 + 局部 AGENTS.md 同步）。

## 结构与语义（拍板固化）

- `llm_endpoints.items[]` 每项必填 `default_model`（非空模型名，≤300 字符，与 `ModelTestRequest.model` 上限一致）；`llm_models` 无顶层 `default`（带 `default` 直接校验拒绝）。
- 步骤合法组合：双 `null`（跟随默认接入点+其默认模型）、接入点+空模型（该接入点默认模型）、接入点+模型；**「无接入点、有模型」校验拒绝**——Wimp 拍板的规则：模型名只在某个服务商处有效，不固定接入点则切换默认接入点时会拿别家格式模型名调用。
- 解析：接入点 = `steps[s].endpoint || llm_endpoints.default`；模型 = `steps[s].model || endpoints[该接入点].default_model`。`resolve_llm_steps` / `resolve_models` 因此需要 `endpoints` + `default_endpoint` 关键字参数。
- `pipeline_runs.config_snapshot` 形态不变（解析后的模型/ reasoning/最终接入点 key）；七个 LLM adapter 零改动。

## 迁移（20261106150000_move_default_model_into_endpoints.sql）

- 硬要求「迁移前后每步解析结果完全一致」。默认接入点的 `default_model` 取旧 `llm_models.default`；其他接入点取**步骤目录顺序**中第一个显式引用它的步骤的模型——jsonb 对象不保留键序，目录顺序在 SQL 里硬编码数组（与 `LLM_STEPS` 一致，改步骤清单必须同步改迁移注释与顺序）。
- 未被引用的接入点直接 RAISE 中止（报错含 key），由管理员先在控制台处理；不给猜测值。
- 「有模型、无接入点」步骤固定到当时默认接入点；模型恰等于该接入点新 `default_model` 的步骤 `model` 置 null（解析不变）。
- 两分区 version 各 +1（旧格式草稿再提交会 409 而不是覆盖）；down 完整逆操作（default 回填、空模型步骤补回接入点默认模型、version -1）。
- **全新部署路径**：`llm_models` 缺席时种子接入点 `default_model` = 兜底值 `deepseek/deepseek-v4-flash`（与 `settings_service.LLM_FALLBACK_DEFAULT_MODEL` 同一值，两处必须同步改）。`_legacy_models()` 不再产出 `default`：等于默认接入点 `default_model` 的步骤写双 null，其余显式绑定「默认接入点 key + 该模型」。注意判据是**接入点的 default_model** 而不是 LLM_MODEL 环境变量——否则 `LLM_MODEL=custom` 时解析结果会从 custom 漂移到兜底值。`LLM_MODEL` 设与不设两种路径都有实库测试。
- 开发库已应用该迁移并刷新 schema.sql（只有版本行 diff）。**部署侧注意：迁移后的库对旧代码不可用**（旧 `validate_llm_models` 要求 `default` 存在），代码与迁移必须同批上线——部署动作由用户自行跟踪，不进 .memory。

## 保存时模型测试统一规则（settings_service）

- 保存 `llm_models` / `llm_endpoints` 任一分区时：每步分别算保存前后解析出的「接入点+模型+reasoning」，三项变了**或**所用接入点连接信息（base_url/api_key_env/api_style）变了就实测保存后组合，相同组合只测一次；新增接入点或 `default_model` 改了的接入点（即使无步骤引用）用 reasoning 关实测一次默认模型。任一失败拒绝整次保存，报错写明步骤（或接入点）与模型。
- 关键教训（M7 变异指向）：比较必须落在**解析后的组合**上，不能比较步骤原始字段——切换默认接入点时原始字段一字不变但解析组合全变。
- `test_llm_model` 的探针核心抽成 `_probe_model(model, reasoning, endpoint, operation)`；接入点级探针不走 step 校验。

## 踩坑（已入 pitfalls 的不重复）

- plpgsql `RAISE EXCEPTION` 不带括号：`RAISE EXCEPTION '格式 %', arg`，写成函数调用式 `RAISE EXCEPTION ('...', arg)` 是语法错误。
- jsonb 取值比较：`step ->> 'model' = item ->> 'default_model'`（两边都要 `->>`），`text = jsonb` 无操作符。
- jsdom：`updateStepModelHint` 在 cell 尚未挂到 row 前调用时 `row.querySelector` 找不到节点——挂载后再刷新提示。
- jsdom：`FakeSettingsServer` 的分区保存成功路径会重渲染页签，`models-save-status` 节点被重建且为空（成功文案写在旧节点上）；保存成功断言走 `#toast`，失败（不重渲染）才可断言状态节点。
