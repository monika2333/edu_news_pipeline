## 教训（多条已进 workflow.md/pitfalls.md）

① 真实 Postgres 测试（临时表模式）抓到 fake-cursor 漏掉的 UPDATE 占位符顺序 bug——新增 UPDATE...FROM SQL 必须配真实 DB 测试。② 变异脚本 `git checkout -- file` 会把功能提交后的未提交微调一并还原（实际发生两次）：任何后续微调必须立即 commit 再重跑变异。③ 「行为被后续清理代码掩盖」的变异要安排可区分观察点。④ jsdom bootPage 在 init 完成前就可能返回，点击 tab 需重试等待；renderDiscardList 期间反复点击会把列表卡在「加载中」。
- 截图方案：无登录凭据时用 TestClient 依赖覆盖渲染页面 HTML，`/static/` 重写同源后 http.server 托管快照，browser-use 改 viewport 截 1280/480；before 用 `git checkout HEAD~1 -- <文件>` 临时回退渲染后恢复。
- 合并冲突要点：adapter 层统一收 terms（service 层 normalize_search_terms 切词）；放弃页恢复/列表 terms 化同步改 core/service/routes/测试；harness /decide 用 reviewRecord 模型，放弃页条目放行语义= `if (record && 版本不符) 409`（写反成 `!record ||` 会让 J3 挂）。
