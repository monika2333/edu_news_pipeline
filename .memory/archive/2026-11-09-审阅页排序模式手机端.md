# 审阅页排序模式手机端可用性改造

日期：2026-11-09
合入：`70febf4`（功能）+ `b5288b7`（自动排序按钮居中），分支 `review-sort-mobile` 快进合并

## 背景

用户反馈「排序模式」在手机上「标题显示不全、拖拽非常奇怪、根本不可用」。用真实路由渲染的静态夹具
（TestClient 依赖覆盖 + `/static/` 同源托管）配合 Playwright（390×844、DPR 3、`has_touch`、真实
CSS/JS/Sortable）取证后，问题是一串叠加的：

1. **卡片被压成竖排**：`components.css` 的移动端 `.card-header { flex-direction: column }` 是给普通
   卡片（勾选框 + 标题 + 操作）设计的，压过了 `review.css` 的排序卡横排规则（后者只覆盖了
   `align-items`）——⋮ 手柄独占一行并居中、标题另起一行，卡片 105px 高。
2. **标题把列表撑出屏幕**：`.review-items` 缺 `min-width: 0`，单列轨道 `minmax(auto, 1fr)` 按
   nowrap 标题的 min-content 撑到 459px（容器 359px、屏幕 390px），标题右侧约 100px 在屏幕外，
   整页可横向拖动。
3. **整卡都是拖拽把手**：`initReviewSortable` 在 `innerWidth <= 768` 时把 `handle` 设成
   `undefined`，且没有 `delay`——手指落在卡片正文就进拖拽态、`touchmove` 被 `preventDefault`，
   超过一屏的列表根本滚不动。
4. **工具条排成四行还留空格子**：隐藏的搜索/全选/查重仍占着 grid area；退出排序只有 43px 高、
   `position: static`，列表一长就得滑回顶部才能退出。
5. **轻点标题会打开原文**（`target=_blank`），排序时误触就跳走。

## 改法

`review.css`：

- 移动端排序卡恢复横排（`.review-grid.sort-mode .card-header { flex-direction: row }`），标题
  `-webkit-line-clamp: 2` 两行显示（一行只能看十来个字，排序时分辨不出条目）。
- `.review-items { min-width: 0 }` 收住横向溢出（普通模式本来就是 359px，无副作用）。
- ⋮ 手柄：44px 命中区、`touch-action: none`、关掉 `-webkit-touch-callout` 与文字选择。
- 排序模式工具条改成两行并吸顶：
  `grid-template-areas: "sort reorder" / "preview archive"`，退出排序 `min-height: 44px`。
  吸顶只给两行（122px），避免遮掉太多列表。
- 移动端排序时标题链接 `pointer-events: none`，不接管点击。

`review_tab_sort.js`：

- 始终 `handle: '.drag-handle'`（移动端不再整卡可拖）；移动端 `delay: 120 + delayOnTouchOnly`、
  `touchStartThreshold: 4`，`scrollSensitivity/scrollSpeed` 只在移动端放大。
- 桌面端参数全部等于 Sortable 默认值（`delay: 0`、`delayOnTouchOnly: false`、
  `touchStartThreshold: 1`、`scrollSensitivity: 30`、`scrollSpeed: 10`），1440px 截图与改动前
  **逐像素相同**。
- `group: { pull: true, put: true }` 不变：跨组拖拽仍会改写该条 `is_beijing_related` /
  `sentiment_label` 并落库（用户 2026-11-09 明确选择保持现状）。

`review.css`（顺带修的老 bug）：「自动排序」（`.sort-only`）显示态是 `display: inline-flex`，
按钮成了 flex 容器、文字是 flex item，`.btn` 的 `text-align: center` 对它不生效。宽度被内容撑满时
看不出来（桌面 95px 宽、文字 61px、左右各 17px），手机端拉伸后左右变成 17/84 才露馅。补
`align-items: center; justify-content: center` 后 50/50，桌面仍是 17/17。

## 验证

- jsdom（`tests/js/review_sort_flow.test.js`）：新增 **R5**（duty / admin 各一条：用
  `Object.defineProperty` 把 `innerWidth` 改 390，替换 `window.Sortable` 构造函数记录 options，
  断言 `handle`、长按门槛、跨组参数）与 **R6**（桌面参数）。pytest 包装层
  （`tests/test_review_sort_js_behavior.py`）改为同时渲染 `/duty` 与 `/admin/review`。
- 变异 4 条全部 KILLED：恢复整卡拖拽、去掉长按门槛、阈值回到 1px、禁止跨组拖拽；还原后文件哈希一致。
- 真实触摸（Playwright + CDP `Input.dispatchTouchEvent`）：卡片正文上滑动 → 未起拖、9 次
  touchmove 全部 **未** `preventDefault`；手柄按住 220ms 再拖 → 起拖、touchmove 全部被接管。
- 几何：手机端卡片 359px、`documentElement.scrollWidth` = 390（溢出 0）、标题两行、手柄 46px、
  工具条 122px 两行；滚动到 55% 时退出排序仍在视口内（top=13）。桌面端截图 sha256 与改动前相同。
- 全量 pytest：worktree（`b5288b7`）与合并后的 main 各 **1898 passed**。
