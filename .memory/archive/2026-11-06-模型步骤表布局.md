# 模型步骤表第二列布局与「跟随默认」提示

日期：2026-11-06　合入：68aebb3

## 症状

用户在 `/admin/settings` 的「默认模型与流水线步骤」看到两个问题：

1. 只要把某个步骤从「跟随默认」切成「指定」，该行就变成两行：第一行是模式下拉 + 一段「跟随默认（接入点：… · 模型：…）」，第二行才是接入点下拉与模型输入框，左缘与模式下拉对不齐。
2. 已经切到「指定」了，那行「跟随默认（…）」的灰字照样显示。

另外截图里「步骤」列被压到逐字断行（`摘要生 / 成`、`相关性 / 评分`）。

## 诊断

- 旧实现把「模式下拉 / 跟随提示 span / 接入点下拉 / 模型输入框」四件东西平铺在同一个 `td` 的行内流里，靠 `hint.hidden = !follow` 切换显隐（`models_tab.js` 的 `updateModelsFollowHints`）。提示长约 370px，在流里就把两个控件挤到第二行；换行后的内容从单元格左缘起排，于是看起来「错位」。
- 表格是 `table-layout: auto`，第二列的提示文本（长模型名/接入点名不含可断点）反过来决定列宽，把第一列挤到逐字断行。
- **「指定模式下仍显示提示」在 HEAD 上复现不出来**：`hint.hidden = !follow` 从建页起就有，jsdom 用例 S2/E1 也锁定过「指定行提示 hidden」。因此现场那台跑的多半不是这份 `models_tab.js`（部署副本落后 / 旧会话页面），或 `updateModelsFollowHints` 在渲染末尾中途抛错导致后续行都没被隐藏（`buildStepRow` 建行时不设 `hidden`，只有那一趟统一收尾会设）。两种情况都可以用「直接打开 `/static/js/settings/models_tab.js` 搜 `hint.hidden`」+「看 Console 有无报错」排除。
- 结论：即使线上是部署问题，这套「常驻节点 + 布尔 hidden 切换 + 文案永远写跟随默认」的写法本身就该改——它让「指定模式残留跟随默认文案」在结构上成为可能。

## 方案（已落地）

第二列改成「模式槽 + 内容槽」两段（`div.step-mode > select.step-model-mode + div.step-content`），**内容按模式重建**而不是切换显隐：

- 跟随默认：内容槽只放一个 `span.step-follow-hint`，文案 `跟随默认 · <接入点 label> / <默认模型>`，带 `title`，`nowrap + ellipsis`。
- 指定：内容槽放 `div.step-custom`（接入点下拉 + 模型输入框），此刻 DOM 里根本没有「跟随默认」这段文字。
- 默认模型输入框变化时只改写跟随行的提示文本（`updateModelsFollowHints`），不重建整格——重建会把用户正在输入的模型输入框换掉，抢走焦点。
- 切换模式用 `replaceChildren` 语义（`clearEl` + 重建）；接入点改动就地清空模型输入并清该行测试结果，不重建下拉以保留焦点。
- 草稿里新增只读字段 `lastEndpoint` 记忆「切回指定时回到上次的接入点」（旧实现靠隐藏的 select 元素记住；节点被移除后需要显式记忆）。不参与保存（`buildModelsSaveValue` 只取 model/reasoning/endpoint）。

CSS（`settings.css` 步骤表段）：

- `.step-mode` 两列 grid（`max-content` + `minmax(0,1fr)`），模式下拉 `min-width: 6.6em`——否则「跟随默认」/「指定」两个选项会让整列左右跳。
- `.step-custom` flex：接入点下拉固定、模型输入 `flex: 1 1 14em; min-width: 0`。
- 列宽：第一列与 reasoning 列 `width: 1%` + `nowrap`（步骤名按内容收缩、不再逐字断行，复选框居中），第二列 `width: 100%` 吸收剩余宽度；测试结果 `white-space: nowrap`，让「测试」列按「按钮 + 结果」实际宽度收缩，结果出现时行高不变。
- `@media (max-width: 900px)`：模式槽与内容槽上下堆叠、下拉 `justify-self: start`、提示允许换行、控件可换行。

## 行为变化（会碰测试的地方）

- 「指定」行不再有 `.step-endpoint-select` / `.step-model-input`；「跟随默认」行不再有下拉与输入框。需要读接入点下拉的用例必须先 `switchStepMode(..., 'custom')`（E4/E17 已按此调整）。
- 提示文案变了：`跟随默认（接入点：X · 模型：Y）` → `跟随默认 · X / Y`（S2/E1 已同步）。
- 断言「指定行不含跟随默认文案」只能看 `.step-content`——模式下拉自身就带「跟随默认」这个 option，看整个单元格会假失败。

## 遗留

- 若线上改后仍显示「跟随默认」灰字，先确认服务器部署副本与浏览器 Console 报错，不要再去改提示的隐藏逻辑——现在指定模式压根不渲染它。
