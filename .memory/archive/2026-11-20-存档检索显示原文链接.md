# 检索抽屉「报送存档检索」显示条目原文链接（2026-11-20）

## 用户反馈

在检索抽屉的「报送存档检索」里搜出来的重点关注舆情条目，只显示来源「（小红书）」「（微博）」这类字样，不显示它自己的链接；这个链接其实在存档里（存档库详情页的条目 meta 行能看到），理论上检索结果里也应该能显示。

第一版交付后用户觉得链接另起一行「好难看」，指定形态为拼回来源括号内：`（小红书 https://xhslink.cn/o/GGCwbSlHt9）`。

第二版上线后用户又发现多条链接时拼接错位：「（小红书 ； https://a https://b）」——分号跑到了来源名后面、两个链接之间没有分隔。正确形态应是「（小红书 https://a ； https://b）」。

## 根因

**展示层遗漏**：报送文本解析时 `src/domain/submission_archive_parser.py` 的 `_extract_source()` 会把正文末尾来源组 `（来源 链接）` 里的 URL 抠出来存 `submitted_report_items.urls`，`search_items()` 的 SELECT 早就带 `i.urls` 且 `/api/submission-archive/search` 原样透传；只有前端 `renderArchiveResults()` 没渲染 `urls`（栈对照：存档库详情页 `detailItemMetaHtml()` 早已渲染）。本地库现状：重点关注舆情条目 41/41 都有 URL（小红书 41、微信公众号 1；同章节北京日报 2 条没有），其他章节基本为空（仅人工编辑过才会补）。

**解析层 bug（多条链接时分号错位的直接原因）**：`_URL_PATTERN = https?://[^\s、）]+` 与来源名切分 `[、\s]+` 都不认全角分号。遇到原文 `（小红书 https://a ； https://b）` 时，URL 被正常抠出，但去掉 URL 后的残留「；」被当成来源名一部分拼进 `source`，存成 `source="小红书 ；"` —— 展示层按「source + 空格 + urls」重建时就成了「小红书 ； https://a https://b」。

## 实现

- **解析层修复**（`src/domain/submission_archive_parser.py`）：新增 `_SOURCE_SEPARATOR_PATTERN = [、；;，,\s]+`，`remaining` 按它切分（「；」不再拼进 source）；`_URL_PATTERN` 字符集排除全角分号/逗号（`[^\s、；，）]+`），`url1；url2` 这种无空格的写法也拆成两条干净链接，而不是一个坏 URL。新导入的条目不再产生脏 source。
- **展示层**（`src/console/web_static/js/manual_filter/search_drawer_archive.js`）：`buildArchiveSourceGroup()` 把正文结尾的来源组重建为 `（来源 链接1 ； 链接2）`，来源名沿用 `appendArchiveHighlight` 的关键词高亮，每个 URL 一个 `<a>`（新标签页 + `rel="noopener noreferrer"`），整组是同一个 `.archive-item-source` span；只接受 `^https?://`；链接文本不做关键词高亮（避免 `<mark>` 拆碎 URL）。多个链接之间统一「 ； 」分隔；**存量数据兜底**：source 末尾的遗留分隔符（`[\s、；;，,]+$`）展示前剥掉。
- 正文为空但来源/链接存在时也照常渲染来源组（不能把条目自带的链接吞掉）；无 `urls` 时组内只有 `（来源）`，与改动前的 DOM/文案一致（原有 jsdom 断言 `（新京报）` 的用例未改仍绿）。
- `css/modules/search.css`：`.archive-item-source .archive-item-link` 行内样式（主题 `--primary-color`、长链接 `word-break: break-all`），没有独立的链接行容器。

## 维护提醒

- 这类条目的 `link_status` 多为 `unmatched`，没有 `article_id`，打不开内容抽屉，必须走外部链接；不要改成只显示来源名，也不要加「原文」按钮。
- 链接形态是用户拍板的「括号内联」：`（来源 链接1 ； 链接2）`，**不要另起一行或单独成块**（第一版单独一行被用户否决）。
- 来源组里 `、；，` 和空白都只是分隔符：解析层不得把它们写进 `source`，展示层多个链接统一用「；」分隔。全角分号必须排除出 URL 字符集，否则 `url1；url2` 会被吞成一个坏 URL。
- **存量脏数据**：旧解析器已入库的 `source`（如「小红书 ；」）没有回填，抽屉展示时会剥掉末尾分隔符；存档库详情页 meta/CSV 导出仍显示原始 `source`。要彻底清干净需另做一次性数据清理（未做，避免擅自动线上数据）。
- `submitted_report_items.urls` 是存档条目的权威字段（见 `docs/data_flow.md` 报送存档节），不要把 URL 写回 `source`/`body` 来「顺便显示」。
- 改动校验/展示口径时记住：`/api/submission-archive/search` 的响应必须继续带回 `urls`，否则前端会静默退化成只剩来源名。
