## 与 2026-10-20 放弃原型的关系

原型把四个评分提示词塞进 `app_settings.external_filter_prompts`，空串表示内置版本，
版本标签为 `custom:{分区版本号}`；该方案已放弃并清理。本次没有复用它的存储：
正文与历史改放独立 `prompt_revisions` 表，当前版本 = 该 key 的最大 revision，
每次保存自动生成 `vN`，文件只在数据库没有该 key 时回退。原型遗留的三个未决点
本次实际落地为：单篇同步试跑（不转后台任务）、自动 `vN`（不用 `custom:`）、
没有做「从筛选页文章直接重评」。

## 存储与版本语义

- `prompt_revisions(id, prompt_key, revision, content, note, created_at, created_by_user_id)`，
  `(prompt_key, revision)` 唯一；只追加，不修改历史。
- `content` 只保存 `<prompt>...</prompt>` 内的有效模板；文件里的标题/说明只是文档。
- 首次保存文件来源的提示词时，同一事务先补一条「初始文件版本」baseline，再写新版本；
  恢复旧版本 = 以旧内容新增 revision（仍在编辑器里确认后再保存）。
- 为什么不能只靠手改 `VERSIONS`：`prompt_version` 会写进
  `news_summaries.external_importance_raw`，并被 `score_feedbacks`、聚类反馈统计按
  `prompt_key + prompt_version` 关联；内容变了不换版本会让旧反馈错绑到新评分。
- 评分提示词的版本继续写文章；京内判定不写 `prompt_version`，历史只用于回看/恢复。

## 流水线接入

- `src/adapters/prompt_store.py`：`load_active_prompts(adapter)` 一次解析 5 个提示词
  （DB 优先、文件回退）；`external_filter.run` / `geo_classify.run` 在每轮开头调用一次，
  把模板传给线程，同一轮内容和版本严格一致。
- `external_filter_model.call_external_filter_model` 与 `llm_beijing_gate.call_beijing_gate`
  增加可选 `prompt_template`；不传时仍走文件回退，单测无需连 DB。
- 不再逐篇文章读 `VERSIONS`，也不再依赖 adapter 的模块级 `_PROMPT_CACHE` 作为生产路径。

## 控制台

- 页签数据走 `GET /api/admin/prompts`，不塞进 `app_settings`；保存 `PUT
  /api/admin/prompts/{key}`，历史 `GET .../versions`，单版本 `GET .../versions/{id}`。
- 全部管理员权限；冲突 409、校验 422、未知 key 404、非管理员 403。
- 编辑器按 key 保存草稿，切换提示词不丢；`promptDraftsDirty()` 纳入未保存离开守卫。
- 历史面板「查看」按需取正文，「恢复」只把旧内容载入编辑器，保存后成为新版本。
- 文件来源首次保存时由后端补 baseline；历史里可恢复 baseline，等价于「还原为文件默认」，
  没有另设按钮。

## P2 试跑

- `POST /api/admin/prompts/{key}/test`，请求 `{article_id, content?}`；`content` 为空用
  已保存版本，传了就是编辑器草稿（与服务端已保存内容相同则不标草稿）。
- 只读 `news_summaries`：标题、来源、摘要、正文、情感、京内外、`score_details`；不写
  `news_summaries`、不写 `score_feedbacks`、不改文章状态。
- 评分提示词返回分数、当前阈值、是否通过、原始输出、耗时、版本（草稿/vN）和文章当前
  生产分数/`prompt_version`；京内判定返回 JSON 结论 + 理由。
- LLM 失败/无法解析以 200 + `error` 回显，保留原始输出；文章不在摘要库（raw-only）或
  没有正文返回 404/422。
- 前端试跑卡片在编辑器下方；选文章复用全局文章检索抽屉的选择模式
  （`body[data-search-drawer-mode="pick"]`），只显示全库文章检索，隐藏 tab、浮动入口、
  「原文」和评分反馈，卡片按钮是紧凑的「选这篇」。
- 选择模式不读写 `search_drawer_open` / `search_drawer_tab` / `search_filters` 三个共享
  localStorage 键；三页（筛选/值班/存档）的抽屉测试必须一起回归。

## 踩坑

- 项目没有 `.btn-sm` 定义：`btn btn-primary btn-sm` 实际仍套 `.btn` 的 10×24/min-height 40px，
  在检索卡片标题行会变成大蓝块；试跑选文章按钮已改为专属 `.search-pick-btn` 紧凑描边样式。
- 校验类测试（空正文/未知文章）即使预期在调用 LLM 前抛错，也必须把 LLM 调用替换成
  「一被调用就失败」的桩；否则校验被变异掉时测试会真实请求模型（实测一次空正文变异
  跑了约 40s 的真实调用）。`_patch_common` 已默认装这个桩，需要 LLM 的用例再覆盖。
- 共享搜索抽屉的选择模式必须绕开三个共享 localStorage 键；用 body data 属性切模式，
  不要改引用页的默认行为。
