# 用户拍板的约束（「别改回去」清单）

这里记录用户明确拍板过的行为约束。**改动这些地方之前先对照本文件**——很多「优化」是用户明确否决过的，不要好心改回去。相关细节见 `archive/` 对应文件。

## UI 形态

- **原文抽屉头部（2026-10-20 定稿）**：元信息行 = `分类徽章 + N 分 + | + 来源 + 收录时间`（右侧原文链接）；可见文本无「重要性分」四字；分数**无悬浮 title**；**无「正文 N 字」**（charCount 计算与展示已整体移除）；竖线跟分类组走（有分类才有）。以上均为用户逐项拍板，曾专门提交删掉悬浮提示（e792b20）。
- **历史班次列表**：值班人名字显示为同行 `· 张三`，不带「值班人：」前缀（用户嫌前缀啰嗦）。
- **全站检索框统一空格分词多词检索**（2026-10-20 拍板，取代 2026-10-08「账号管理页搜索框不改」的例外）：账号管理页账号搜索、报送存档人工回链候选、两套原文抽屉的正文检索都必须支持空格分词；新增检索框不得只做整串子串匹配（细节见 [archive/2026-10-20-全站检索框多词改造.md](archive/2026-10-20-全站检索框多词改造.md)）。
- 细化筛选：折叠工具栏形态；「筛选」按钮无 caret 小三角（用户明确删掉）；「清空筛选」唯一入口在 meta 行之后、描边小按钮样式（行内不重复放）；放弃页头部的「清空筛选」复刻该按钮**视觉**但类名不共用（委托劫持，见 pitfalls）。
- 清理旧新闻的确认用 `window.confirm`（与批量放弃一致）；撤回不设条数上限。

## 功能语义

- **检索语义（后端）**：标题/原文等表达式字段全词 AND + `llm_summary` 至少一词 OR（整组括号）；>10 词 422。前端高亮**直接用响应 `terms` 字段**，不要再切一遍词。值班汇总/复核页签的前端内存过滤为全词 AND，不设词数上限。报送存档人工回链候选（`link-candidates`）同样是逐词 AND（每词标题或摘要任一命中）、去重后 >10 词 422；原文抽屉正文检索只做逐词高亮定位，不做结果过滤。
- **图片一律剥离**：流水线纯文字；html_to_markdown 用统一剥图版；xinhua 图说文字保留。
- **千龙默认 1 页**：用户主动把默认值从 3 收紧为 1（与每小时 1 页来源基线一致）；`QIANLONG_PAGES` 仅作上调覆盖。
- **无手动刷新聚类**：刷新按钮及 force_refresh 全链路已删净（249b63e），新新闻进聚类最多延迟 5 分钟（计划任务重建）属预期。聚类缓存唯一重建入口 = 计划任务 refresh-manual-clusters；`/api/manual_filter/trigger_clustering` 底层的 `refresh_clusters()` 前端无调用者，**勿误判为死代码删除**。
- **无命中条目**（报送存档）仅允许「标记为已报送/撤销」，仍拒绝 not_submitted；不做人工绑定更早条目、不做低于阈值候选展示（用户只拍板了方案 A）。
- 自动排序关键词：放设置页**高级**页签三文本块；类别允许留空（全空保存要确认）；跨类别重复词保存**报错**（不静默容忍）。

## 流程与工程

- **合并能快进就 ff-only**，不产生 merge commit（用户 2026-10-08 明确要求，见 workflow.md）。
- **委托书式任务流程**：文件范围硬约束 + 必做变异测试（见 workflow.md）。
- **记忆只在 main 合并后更新并单独提交**：worktree 内 `.memory/` 只读；完整规则见 `.memory/README.md`「维护规则」第 2 条（2026-10-20 拍板）。
- 数据库变更只做加法；`manual_clusters` 不加报别维度（权威规则见根 `AGENTS.md`）。
- `.audit/`、`.discussion/`、`.incidents/` 三个过程文档目录**不需要**（2026-10-20 拍板）：它们与 `.memory/`（决策/踩坑/交付）和 git 历史职责重叠，且其按日期目录 + README 索引 + 文件名前缀的归档规则对单人 + AI 协作维护成本过高，收益不抵成本。
