# 用户拍板的约束（「别改回去」清单）

这里记录用户明确拍板过的行为约束。**改动这些地方之前先对照本文件**——很多「优化」是用户明确否决过的，不要好心改回去。相关细节见 `archive/` 对应文件。

## UI 形态

- **加分词典页签（2026-10-20 定稿）**：两组分区「加分词在上、减分词在下」，每组末尾有独立添加入口；写入顺序与展示一致（先加分、后减分）；**即时保存**（无「保存加分词典 / 放弃修改」按钮）：值提交或焦点离开整行自动保存、删除立即写库、删最后一条弹确认；完全空白行只作本地草稿、半行/非法值标红并拦住保存；状态行显示保存结果和最后修改；副标题与初始「修改后自动保存」提示已删除；「生效说明」不再解释先加分还是先减分。
- **系统设置页形态（2026-10-20 定稿）**：左栏竖向导航（>1200px 两栏，≤1200px 折叠为顶部等宽页签），「高级」归在「系统」组、不再做右对齐小字入口；顶部页签版已被否决。每个分区有页头（长标题 + 一句话说明），内容按 `.settings-card` 分卡片；短标签/页头文案映射在 `core.js` 的 `SETTINGS_TAB_META`。
- **高级页关键词编辑（2026-10-20 定稿）**：默认芯片视图，逐条删除、内联输入回车添加；「批量编辑」展开原生 textarea 做整段修改。textarea 是唯一数据源（`readValue` 只读它），芯片/添加框只是视图；来源别名也芯片化（显示「原名称 → 标准名称」）。
- **数据源页（2026-10-20 定稿）**：每小时来源是单列列表 + 手风琴账号面板，同时只开一个、默认折叠；**不要恢复页面级管理模式**——展开面板就是编辑面，芯片常驻「启用开关 + ↗ 打开主页 + × 标记删除」，添加账号常驻，刷新名称仅在展开时出现。删除为面板内标记 + 本面板确认条（只处理本来源标记，跨来源批量删除已移除）；每日任务行名称与标题左对齐、无开关占位。
- **原文抽屉头部（2026-10-20 定稿）**：元信息行 = `分类徽章 + N 分 + | + 来源 + 收录时间`（右侧原文链接）；可见文本无「重要性分」四字；分数**无悬浮 title**；**无「正文 N 字」**（charCount 计算与展示已整体移除）；竖线跟分类组走（有分类才有）。以上均为用户逐项拍板，曾专门提交删掉悬浮提示（e792b20）。
- **筛选页单条卡片分类标签（2026-10-20 定稿）**：sentiment 徽章与「京内: 是/否」两处合并为一个 `badge search-category-badge` 标签（京内正面/京内负面/京外正面/京外负面），不再分别展示 sentiment 原文和京内外字段；口径统一走 `manual_filter/utils.js` 的 `articleCategoryBadge`（筛选卡片、检索卡片、两套原文抽屉共用，别处不要另写判定），地域或情感未就绪时卡片留中性「-」占位、检索卡片与抽屉不渲染徽章。
- **历史班次列表**：值班人名字显示为同行 `· 张三`，不带「值班人：」前缀（用户嫌前缀啰嗦）。
- **全站检索框统一空格分词多词检索**（2026-10-20 拍板，取代 2026-10-08「账号管理页搜索框不改」的例外）：账号管理页账号搜索、报送存档人工回链候选、两套原文抽屉的正文检索都必须支持空格分词；新增检索框不得只做整串子串匹配（细节见 [archive/2026-10-20-全站检索框多词改造.md](archive/2026-10-20-全站检索框多词改造.md)）。
- 细化筛选：折叠工具栏形态；「筛选」按钮无 caret 小三角（用户明确删掉）；「清空筛选」唯一入口在 meta 行之后、描边小按钮样式（行内不重复放）；放弃页头部的「清空筛选」复刻该按钮**视觉**但类名不共用（委托劫持，见 pitfalls）。
- 清理旧新闻的确认用 `window.confirm`（与批量放弃一致）；撤回不设条数上限。
- **提示词页签与试跑按钮（2026-10-21 定稿）**：提示词页签复用系统设置页左栏导航；试跑卡片在编辑器下方，选文章复用全局文章检索抽屉的选择模式。「选这篇」必须是紧凑描边小按钮，**不要用全局 `btn-primary` 大按钮**（项目没有 `.btn-sm`，`btn btn-primary btn-sm` 实际仍是 40px 高主按钮，用户明确嫌大/突兀）。
- **汇总审阅预览弹窗形态（2026-10-21 定稿）**：题头（标题/期号/日期）**不单独成块**，直接是预览 textarea 的前三行 + 空行 + 正文，与正文同字体；「包含题头」开关放底部与「复制内容」同行（开关靠左、按钮靠右；开关隐藏时按钮仍靠右），默认打开、选择存 `localStorage.manual_filter_preview_header`；备选桶不显示题头也不发请求；关闭按钮是右上角 1.5rem 的 ✕（不是「关闭」文字按钮），Esc 也能关。**Esc 必须捕获阶段注册并截断**：原文抽屉/检索抽屉/查重弹窗的 Esc 都在 document 冒泡阶段且注册更早，不在捕获阶段抢下就会先关掉底下的抽屉。
- **筛选页「采纳」「备选」报别快捷菜单（2026-10-21 拍板）**：桌面右键、手机长按是同一入口（手机没有右键），把该条直接归入另一报别；长按必须先弹菜单，抬手后浏览器补发的 click 绝不能落成「归入当前报别」的轻点决定（同一 radio 的短时 click 守卫）。语义仍是单次报别覆盖，不切换「归入报别」状态（细节见 [archive/2026-10-21-触屏长按决定菜单.md](archive/2026-10-21-触屏长按决定菜单.md)）。

## 功能语义

- **检索语义（后端）**：标题/原文等表达式字段全词 AND + `llm_summary` 至少一词 OR（整组括号）；>10 词 422。前端高亮**直接用响应 `terms` 字段**，不要再切一遍词。值班汇总/复核页签的前端内存过滤为全词 AND，不设词数上限。报送存档人工回链候选（`link-candidates`）同样是逐词 AND（每词标题或摘要任一命中）、去重后 >10 词 422；原文抽屉正文检索只做逐词高亮定位，不做结果过滤。
- **提示词存储与版本（2026-10-21 拍板）**：5 个提示词正文存独立 `prompt_revisions` 追加表，当前版本 = 该 key 的最大 revision；每次保存自动生成 `vN`，不可手改；历史可回看/恢复（恢复 = 以旧内容新增版本）；`config/prompts` 文件只在数据库没有该 key 时回退，`VERSIONS` 不再是生产版本源。**不要改回 `app_settings.external_filter_prompts` 分区**（2026-10-20 原型已放弃并清理）。评分提示词版本写入文章并绑定 `score_feedbacks`，京内判定不写版本。
- **提示词试跑（2026-10-21 拍板）**：设置页单篇同步试跑，只读 `news_summaries`，不写库；结果展示分数/判定、阈值、原始输出、版本（草稿/vN）与文章当前生产结果。选择模式不得读写筛选/值班/存档三页共享的 `search_drawer_open` / `search_drawer_tab` / `search_filters`。未做批量试跑、后台任务、从筛选页文章直接重评。
- **期号是取材日的线性函数（2026-10-21 拍板，2026-10-26 修订取数口径）**：综报与晚报各一条序列，每个日历日 +1，停报几天就跳几期；综报轴 = 报送日，晚报轴 = 取材日（= 报送日 − 1，走 `default_compiled_date` 口径）；年度期号与总期号同步递增、**跨年不归零**。**不要做成计数器表、不要按报送动作 +1、不要允许手改、不要加设置项**。
  **预览取数（2026-10-26 拍板「方案 A」）**：锚点一律是**报送日**——管理员 = 今天，值班编辑 = 所查看班次的 `coverage_date`（班次下拉里显示的那个日期），所以看历史班次显示的是当时那一期，不会同步到今天。顺序是**归档优先、公式兜底**：该报送日已有归档就直接用它的 `issue_no` 与日期；没有才以最近一条可解析归档按天数差推算（天数差可为负，历史班次往回推）。「同一期 / 基准过旧」两类提示已删除，只在完全没有基准时提示一句。细节见 [archive/2026-10-21-预览题头期号推算.md](archive/2026-10-21-预览题头期号推算.md)。`issue_no` 因此必须保持可严格解析（`总第N期` / `YYYY年第N期（总第M期）`，全角括号），带后缀的脏数据会掉出基准。
- **图片一律剥离**：流水线纯文字；html_to_markdown 用统一剥图版；xinhua 图说文字保留。
- **千龙默认 1 页**：用户主动把默认值从 3 收紧为 1（与每小时 1 页来源基线一致）；`QIANLONG_PAGES` 仅作上调覆盖。
- **无手动刷新聚类**：刷新按钮及 force_refresh 全链路已删净（249b63e），新新闻进聚类最多延迟 5 分钟（计划任务重建）属预期。聚类缓存唯一重建入口 = 计划任务 refresh-manual-clusters；`/api/manual_filter/trigger_clustering` 底层的 `refresh_clusters()` 前端无调用者，**勿误判为死代码删除**。
- **无命中条目**（报送存档）仅允许「标记为已报送/撤销」，仍拒绝 not_submitted；不做人工绑定更早条目、不做低于阈值候选展示（用户只拍板了方案 A）。
- 自动排序关键词：放设置页**高级**页签三文本块；类别允许留空（全空保存要确认）；跨类别重复词保存**报错**（不静默容忍）。
- **加分词典分值范围保持 −100～100**（2026-10-20 拍板）：不要靠改大负数做硬淘汰——`score` / `keyword_bonus_score` 是 `numeric(6,3)`（最小 −999.999），−1000 会让整批评分写库溢出。硬淘汰另做独立排除名单。
- **评分排除名单优先于加分词典**（2026-10-20 拍板并完成，5d44e09）：全局一份 `app_settings.score_exclusion_keywords`（有序字符串数组，空数组合法）；标题/正文/关键词子串大小写敏感命中即淘汰，不计算加分、不调用模型、`status=filtered_out`、`score=NULL`、`raw_relevance_score=NULL`、`score_details.skip_reason=keyword_excluded`、不写 `news_summaries`。设置页在「加分词典」页签表格下方以独立卡片即时保存，不新增页签；两个分区版本/脏标记/409 重载互相独立。
- **21经济网来源口径（2026-10-20 拍板，b8c72f8）**：数据源显示名「21经济网」，来源 key `21jingji`，账号=栏目（当前只「宏观」= `/channel/politics/`）；**所有稿件来源固定「21世纪经济报道」**，不随栏目/账号名变（同北京号→北京日报）。每轮只抓频道第一页 20 条（15 分钟一轮；站点无服务端翻页，「查看更多」接口已 404）。来源开关默认关闭，账号由迁移预插、开关由用户在设置页打开。

## 流程与工程

- **合并优先 ff-only；不能快进时直接普通 merge**（2026-10-20 修订，取代 2026-10-08 的强制 ff-only）：能快进就 `git merge --ff-only`；真分叉时普通 `git merge`、产生 merge commit 可以接受，**不要为了 ff-only 额外 rebase 分支**。合并后仍必须跑主仓库全量 pytest（见 workflow.md）。
- **委托书式任务流程**：文件范围硬约束 + 必做变异测试（见 workflow.md）。
- **记忆只在 main 合并后更新并单独提交**：worktree 内 `.memory/` 只读；完整规则见 `.memory/README.md`「维护规则」第 2 条（2026-10-20 拍板）。
- **部署侧待办不进 `.memory/`**（2026-10-20 拍板）：生产/部署侧手工动作由用户自行跟踪；`open-tasks.md` 只记开发进行中事项与未排期候选。
- 数据库变更只做加法；`manual_clusters` 不加报别维度（权威规则见根 `AGENTS.md`）。
- `.audit/`、`.discussion/`、`.incidents/` 三个过程文档目录**不需要**（2026-10-20 拍板）：它们与 `.memory/`（决策/踩坑/交付）和 git 历史职责重叠，且其按日期目录 + README 索引 + 文件名前缀的归档规则对单人 + AI 协作维护成本过高，收益不抵成本。
