# 2026-11-01 提示词历史版本改为就地展开

用户在使用「设置 → 提示词 → 历史版本」时提了三条反馈，这里记代码与 decisions 之外的背景、取舍与验证方式。

## 背景：为什么要改

1. 展开内容挂在**整个版本列表末尾**的两个共享节点（`card.append(list, preview, detail)`）上：点靠上的版本也要滚到底部才看得到，版本攒多后不可用；共享节点还导致「点 A 再点 B，两条按钮都写收起，点 A 的按钮收的是 B 的内容」。
2. 检查结论与案例**一次全渲染**：真实的一次夜间优化运行有 90 个案例（T=5、R=76），6 列表格又带 `min-width: 760px`；2026-10-31 加入确认回放后分数列变成 `58/62` 双分数，窄一点就直接把分数列挤出可视区——用户原话「整个页面甚至都没法完全展开」指的正是分数列横向放不下。
3. 用户还要求「展开/收起」有更直观的提示（小三角）。

## 取舍（代码之外的「为什么」）

- **不做三层折叠**：版本面板 → 自动优化详情 → 案例分组已经是三层。给「案例」再加一层默认收起的区块会让「已修好」也要点三次才看得到，且与「案例默认只渲染第一组」的懒渲染重复。最终形态：二级详情默认收起；展开后直接显示分组头 + 第一组（通常是已修好）的行，其余组点组头才建 DOM。（当天追加拍板后，「本次改动」不再放进二级详情，见文末。）
- **标题行整行不可点**：右侧紧邻「恢复」，整行可点会把「想展开却点了恢复」变成常见误操作，也影响选中备注文字。可点区域只有展开按钮。
- **展开态不做跨重绘持久化**：保存/恢复/切换提示词都会整页重绘，持久化要往 `state.prompts` 加字段（`core.js` 在本次文件范围外），收益只是省一次点击。折中是「同一份 DOM 内收起再展开复用已加载面板」，跨重绘则全部收起。
- **历史记录必须能回退**：`fix_state` 是 2026-10-31 才写入运行记录的字段、无迁移，老记录只有 `bucket` + `candidate_satisfied`。回退规则：`skip_reason` 优先 → `fix_state` → T 看 `candidate_satisfied`（true=fixed/false=unchanged）、R 看 `candidate_satisfied === false`（broken）否则 unchanged。少了这条，所有历史案例会被归成「未变化」。
- **`未变化` 组不能固定在组级的「未达标」**：该组同时装着「T 没修好」与「R 本来就达标、只是没被改坏」两类，组级文案会把后者说错（旧的 6 列表格是按单条 `candidate_satisfied` 给的，改成组级常量是回退）。所以 unchanged 组按单条判定，样式仍用中性 `is-unchanged`。

## 实现要点

- `buildPromptHistoryItem` 每条版本自建 `.prompt-history-panel`（`hidden`），展开时 `fetchPromptRevisionPayload`（payload 由 `revision._payload` 缓存）；成功渲染后置 `loaded = true`，收起再展开走快路径——不重渲染、不闪「加载中…」、二级展开态与「还有 N 条」位置都保留。**这个 `loaded` 第一版漏了赋值**，表现为收起再展开时面板重置，由复核发现并补用例 A11 锁定。
- 手风琴互斥靠 DOM 查询同列表内其它 `.prompt-history-item`，没有新增 state。
- 案例行改卡片式（标题 + 来源/方向 + 分数流 + 状态一行，原因一行），`flex-wrap` + `word-break`，彻底删掉 `min-width: 760px` 的表格容器。
- CSS 注意点：`.prompt-optimization-case-group-body` / `.prompt-optimization-failures-rest` 是 `display:flex`，会压过浏览器默认的 `[hidden]{display:none}`，必须显式补 `[hidden]` 规则（仓库既有多处同样写法）。

## 2026-11-01 追加：本次改动改为第一次展开就显示

用户点开历史版本最先要看的是「替换前 / 替换后」，原先它们藏在二级开关里、要点两次。追加改动把运行头部（结论徽章 / 完成时间 / 模型 / 错误）与「本次改动」直接渲染在版本展开区；二级开关改名「检查结论与案例」，只收检查结论 + 案例（仍默认收起，标签给通过/未通过与修好/改坏计数）。没有文本改动时不渲染空的改动块，避免每条「未改动」运行都多一块空态；`本次改动`/`检查结论`/`案例` 三段顺序不变。
