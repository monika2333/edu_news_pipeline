# 高级设置改失焦即时保存（2026-11-11）

## 背景

高级页签原来分四块（教育关键词、京内关键词、来源别名、自动排序关键词），每块一套「保存X / 放弃修改 / 载入最新配置 + 状态行」，共四对保存/放弃按钮。用户提出：这些块和新闻摘要编辑框一样，改完点到别处就该自动保存，不需要每次点保存。讨论后拍板走「失焦即时保存」，与加分词典、筛选页摘要框的既有形态对齐。

## 拍板（用户逐项确认）

1. **回滚出口**：默认没有任何按钮；只有草稿写不进去（校验失败/409/422/网络错误）时，状态行旁出现描边小按钮「还原为已保存内容」（读本编辑器最后保存成功的本地快照，不发请求）。409 另外给「载入最新配置」（拉服务端最新值）。不做常驻「载入最新配置」。
2. **自动排序三类全空**：去掉 `window.confirm`，直接保存，状态行提示「三个类别都为空，自动排序不会调整条目顺序」。这推翻了 `decisions.md` 里原「全空保存要确认」的口径，已在 decisions.md 同步改写。
3. **范围**：只改高级页四个分区。模型与接入点页签保持显式保存（保存会触发模型实测，且接入点卡片自带保存按钮），加分词典本来就是即时保存。
4. **不加「改动失焦后自动保存」提示**：用户认为这符合编辑习惯，不额外解释（与加分词典当时删掉提示同一口径）。

## 实现要点

- `section_editor.js`：`buildSectionSaveBar` → `buildSectionAutoSaveBar`（只被高级页调用）。
  - 触发：`advanced_tab.js` 在页签根上做一次 `focusout` 委托，`relatedTarget` 在本块内就不提交；同一块里从词表跳到添加框/批量编辑不产生请求。
  - 串行：每分区一个 `state.saving[section]` + `saveQueued`，保存中再触发只排队一次，不并发用同一版本号。
  - **版本冻结**：`saved` 在本编辑器渲染时快照，只被自己的保存成功响应推进。窗口重新聚焦会整体重拉 payload（`reloadSettingsPayload`），若保存时读 `settingsSection(section).version`，就会拿别处升级过的版本静默覆盖别人的修改、409 永不出现。
  - 成功不重绘：只更新状态行与「最后修改」，保留批量编辑展开状态与焦点。
  - 规范化回写：服务端会 trim/去重（`education_keywords`/`beijing_keywords` 静默去重），不写回的话本地脏文本每次失焦都会重复 PUT 并把版本越推越高。`input.syncValue` 只改视图、不触发 `input` 事件，内容相同不重新赋值（避免光标跳到末尾）。
  - 校验失败：不发请求、标红、状态行写原因、批量编辑自动展开但**不抢焦点**（原来的 `revealAdvancedBatch` 会 focus，失焦保存时会把焦点拽回去）。
- `advanced_tab.js`：`readValue()` 契约改为纯取值/校验，返回 `{ value, warning? }` 或 `{ error, reveal? }`；芯片「×」删除后立刻 `commit()`。
- `settings.css`：`.settings-save-bar.is-autosave` 去掉分隔线，状态与「最后修改」同一行（最后修改靠 `margin-left:auto` 靠右）。
- 后端零改动：仍走 `PUT /api/admin/settings/{section}` + `expected_version`。

## 测试与验证

- `tests/js/settings_behavior.test.js` 高级页用例从「点 `.section-save`」改为「派发 `focusout`（relatedTarget=null）」；新增用例：四块无保存/放弃按钮、同块内换字段不保存、保存成功不重绘（批量编辑保持展开、节点不换）、409 给两个出口且还原后版本不偷偷升级、删除芯片立即写库、回车添加只入草稿、三类全空不弹 confirm、校验失败零请求 + 还原回滚、保存中只排队。
- 变异测试 6 条全部 KILLED（每条至少一个用例失败）：
  - M1 不判 `relatedTarget`（同块内也提交）→「同一块内移动焦点不保存」失败
  - M2 删除芯片不 `onCommit` →「芯片逐条删除并立即写库」失败
  - M3 保存时读 payload 当前版本（不冻结）→「整体 payload 重载后…」失败
  - M4 不回写服务端规范化结果 →「关键词服务端去重后回填」失败
  - M5 三类全空重新当错误拦下 →「F17」失败
  - M6 保存中不排队 → 两条「保存排队」用例失败
- 全量 pytest：worktree 1926 passed，合并后主仓库再跑 1926 passed。

## 后续注意

- 不要给高级页加回保存/放弃按钮，也不要改成防抖输入即保存（用户明确要「失焦」这个触发点）。
- 新增同类字段沿用 `buildSettingsTextarea` 的 `options.onCommit`；新增分区沿用 `buildSectionAutoSaveBar`，并补 `applyValue`（否则服务端规范化会造成版本空转）。
- 还原按钮只读本地快照；别改成拉服务端（那样会盖掉用户想保留的草稿，语义也变成「载入最新配置」）。
