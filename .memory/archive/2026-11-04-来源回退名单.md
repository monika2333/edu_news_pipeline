# 2026-11-04 来源回退名单（source_aliases.fallback_names）

## 需求与设计

筛选页人工来源框每次都要手动回退的常见识别结果（《现代教育报》、「某政府官方发布」类）由管理员维护回退名单：新文章做来源识别时，识别结果与名单整串全等就不保存识别来源（写 `NULL`），展示层自然回退到抓取来源。

委托书拍板的关键口径（勿改回去）：

- **写入时处理，不碰读取路径**：判断放在 `enrich-summary` 的 `_detect_article_source()`，与来源归一化同一位置。控制台 `_resolved_llm_source`、`_imports.py` 的 `COALESCE`、审阅页与预览全部零改动。读取时过滤要改分散的 Python/SQL/JS，容易漏。
- **命中必须写 `None` 不写空串**：`COALESCE(sr.manual_llm_source, ns.llm_source, ns.source, '')` 不跳过空字符串，空串会让回退失效（M5 变异专门验证）。
- **精准匹配**：归一化前与归一化后两个名称任一整串全等即命中；大小写、书名号等符号一律不归一（「现代教育报社」「《现代教育报》」不命中）。
- **配置可缺失**：`fallback_names` 是可选字段，线上旧配置行不含它，缺失按空名单处理；校验结果始终包含该字段（运行快照因此可还原当轮名单）。不做数据库迁移。
- 名单只对之后入库的文章生效。

## 实现

- `src/domain/source_aliases.py`：`SourceAliasRules.fallback_names` + 纯规则 `matches_fallback_name(raw, normalized, rules)`（domain 可脱离 worker 测试；`src/domain/__init__.py` 导出）。
- `src/business_config.py`：`validate_source_aliases` 校验（列表、字符串项、strip 后非空、报错含序号）、`resolve_source_aliases` 传递、`snapshot()` 含名单。
- `src/workers/enrich_summary.py`：归一化后判 `matches_fallback_name`，命中写 `None` 并 `log_info` 记文章 ID + 原始名 + 归一化名（`FALLBACK source name ...`；回退后库里不留识别结果，日志是唯一排查线索）。`NORMALIZED` 日志保持不变。
- `src/console/web_static/js/settings/advanced_tab.js`：来源别名卡片第三个 `buildSettingsTextarea`（class `alias-fallback-names`、单位「条」、占位「添加来源名称，回车确认」），`readValue` 返回 `fallback_names`，旧配置 `|| []` 兜底，共用保存栏与 409/422。
- `docs/data_flow.md`：llm_source 段补回退名单语义；`app_settings` 行标注分区含 `fallback_names` 可缺失。

## 坑

- 变异驱动给 node 子进程传 env 必须 `dict(os.environ)` 拷贝后增改；整个替换成最小字典会让 Node 启动即崩 `ncrypto::CSPRNG(nullptr, 0)`（rc=134，非测试断言）。已记 pitfalls。
- worker 层模拟 adapter 时，`未知`/超长在 `detect_source` 返回前已转成 `None`（超长还带 guard 元数据），stub 直接返回 `"未知"` 测不了 worker 的空结果分支。
