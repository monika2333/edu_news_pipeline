## 需求

系统已有「北京号」这种账号型来源（一个账号 = 一个栏目页）。新增新京报的「新京号」来源，当前只接「北京援藏」（`https://m.bjnews.com.cn/mp/296`），要求与北京号同构，后续可在控制台继续添加其他号。

## 站点事实（2026-11-06 实测）

- 号信息：`GET https://api.bjnews.com.cn/api/v101/xjh/xjh_info.php?xjh_id=296`，取 `data.institution_name`（北京援藏）。
- 文章列表：`GET https://api.bjnews.com.cn/api/v101/xjh/xjh_article.php?xjh_id=296&page=N`；每页 10 条、按时间倒序；实测 700 篇，page 71 返回空数组；`data[i].row.content` 即完整正文；`data[i].share_url` 为 `https://m.bjnews.com.cn/detail/<uuid>.html`；`row.publish_timestamp` 为 UTC 秒。
- 详情页不需要抓：抽样 3 篇（含 6147 字长文）与详情页 `.article` 正文比对一致，详情页最多多一行「来源：xxx」。
- 主页 URL：`/mp/296` 可用；`/mp/296/` 返回 404；`www.bjnews.com.cn/mp/296` 返回 404。解析时去结尾斜杠、只接受 `m.bjnews.com.cn`。
- 结尾模板：供稿/来源/编辑/编校/校对/审核等；「供稿：教育援藏团队」含「教育」，不剥会让教育关键词闸门对所有文章放行。

## 设计

- 来源 key `xinjinghao`，显示名「新京号」，稿件 `source` 固定「新京报」（同北京号 → 北京日报）。
- 账号：`normalized_identifier=<xjh_id>`，`profile_url=https://m.bjnews.com.cn/mp/<id>`；输入接受裸 ID、`/mp/<id>`、带 query 的 URL。
- 抓取：`details_in_list=True`，列表一次返回 feed 元数据与正文；`article_id=xinjinghao:<uuid>`，统一由 URL 派生，过滤/去重/入库同源。
- 翻页：默认 1 页（10 条）；`--pages` 是硬上限；`existing_ids` 只过滤、不截停；停止只看原始 `data` 数组空/不足一页。
- 正文：公共 `html_to_markdown` + 站点噪声选择器 + 结尾元信息剥离；空正文抛错，不写 `detail_fetched_at`。
- 账号名：`xjh_info.php` 的 `institution_name` 优先，回退 `#xjh_name_hidden` / 主页 `<title>`（去「的主页」）。
- 迁移：只插 `crawl_accounts` 的 296（北京援藏，enabled=true），不改 `app_settings.crawl_sources`；来源开关由设置页手动打开。

## 验收中抓到并修复的 bug

第一版 `list_items` 用「过滤 existing_ids 后不足一页」作为停止条件。`--pages 70` 补历史时 page 1 全是已入库条目，过滤后为空就直接停，page 2 以下老稿抓不到。修复为只按原始 `data` 数组判断：空数组或原始条数 `PAGE_SIZE` 以下才停；`existing_ids` 只过滤不截停。新增「page 1 全部 existing 仍继续 page 2」用例。同时统一 `article_id` 为 URL 派生，修掉原先 `row.uuid` 与 `share_url` 两套 ID 的不一致。
