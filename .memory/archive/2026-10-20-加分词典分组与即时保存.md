# 加分词典分组展示与即时保存

日期：2026-10-20。合入：b3971a5（ff-only）。相关文件：`src/console/web_static/js/settings/bonus_tab.js`、`src/console/web_static/css/modules/settings.css`、`tests/js/settings_behavior.test.js`。

## 背景与迭代

用户最初反馈 `admin/settings#bonuses` 里加分和减分混在一起、页面视觉空荡，要求「稍微区分一下」。第一版做了行内正负配色 + 顶部统计；用户随后要求**两组分区**，并先要求「先减分后加分」，之后又改为**加分词在上、减分词在下**，写入顺序也统一为「先加分、后减分」。最后用户要求去掉「保存加分词典 / 放弃修改」，改为**即时保存**，并删掉副标题与状态行初始提示「修改后自动保存」。

## 最终行为

1. **分组**：页签内两组「加分词」（上）/「减分词」（下），各自末尾有「＋ 添加加分词 / 添加减分词」入口；组头有颜色点、条数和「命中即加分/扣分」提示；顶部保留三块统计（加分词/减分词/关键词总数）。
2. **写入顺序**：与展示一致，先加分、后减分；被归组的行按目标组末尾排序。`buildValue` 用「未来归组后的顺序」构造 payload——已在目标组的行保持原序，刚改符号的行接在目标组末尾（和 `regroupRow` 的 appendChild 一致），避免保存后归组又触发第二次 PUT。
3. **即时保存**：
   - 分值 `change`（提交/失焦）或焦点离开整行（`focusout`，且 `relatedTarget` 不在行内）触发整段 PUT；
   - 关键词先填、分值还空时不保存也不报错（避免半行状态先弹错），等焦点离开整行再校验；
   - 删除立即写库；删最后一条仍弹 `window.confirm`（防止误清空词典）；
   - 完全空白的行是本地草稿：不写库、不报错、不算未保存修改；只填一半或非法值会标红并拦住整段保存；
   - 保存串行化（`saveInFlight` + `saveQueued`），请求进行中再编辑只排队一次，避免并发 PUT 用同一版本号互相 409；
   - 409 时状态行提示并出现「载入最新配置」，只重载该分区；422/网络错误保留输入并显示原因；
   - 保存成功后把关键词输入框同步为服务端 trim 后的值（保存期间被改过的行不动）。
4. **状态行**：原保存栏位置改为「保存中… / 已自动保存。 / 保存失败…」+ 右侧「最后修改：某人 · 时间」。初始状态为空（用户要求删掉「修改后自动保存。」）。
5. **文案**：副标题整段删除；「生效说明」只保留「命中计分/多个累加」「填完一行、焦点离开即自动保存，历史不重算」两条，不再向用户解释先加分还是先减分。

## 设计取舍

- **为什么整段 PUT**：后端只有分区级保存接口（`PUT /api/admin/settings/{section}` + `expected_version`），没有行级 API；即时保存只能在每次变更时整段写回。
- **为什么不在 `change` 里直接保存所有情况**：从关键词 Tab 到本行分值会触发 keyword 的 `change`，此时分值还空，先保存会先报一次「有未保存的修改」；因此 keyword 的空值场景跳过，等焦点离开整行再校验。
- **为什么行只在焦点离开整行后换组**：在行内 `appendChild` 会打断 Tab 的焦点顺序；`focusout` 用 `relatedTarget` 判断是否仍在行内，离开后才挪。
- **为什么空白行不落库**：新增行天然是全空，若参与保存会立刻触发「关键词不能为空」；把「完全空白」当草稿（不算未保存修改）既符合直觉，也不阻挡正常编辑。
- **未保存守卫**：输入即置 `state.dirty.score_keyword_bonuses=true`（防未失焦就关页）；保存成功按「当前界面 vs 已保存值」重算，不能无条件清零（请求期间可能又有输入）。
- **范围不变**：分值仍限 `−100..100`。`score` / `keyword_bonus_score` 是 `numeric(6,3)`（最小 −999.999），−1000 会写库溢出，且整批 `executemany` 会一起失败；硬淘汰另走排除名单（见下）。

## 测试与验证

- jsdom 设置页行为测试重写为即时保存口径：126 passed；官方入口 `tests/test_settings_js_behavior.py` 通过。
- 主仓库全量 `pytest`：1410 passed（含真实 Postgres 与 jsdom）。
- 真浏览器（Playwright）用拦截 PUT 的方式验证：一次编辑 1 个 PUT；只填关键词跳到分值不报错/不保存；删除立即 PUT；409 显示冲突、本地值保留、「载入最新配置」出现；验证过程没有写库。
- 新增/改写的用例覆盖：分组顺序、写入顺序、行归组、两个添加入口、空行不算未保存、半行拦截、删除最后一条确认、串行提交、409 重载。

## 踩坑

- `saved.value.forEach(addRow)` 会把 index 当第二个参数传给 `addRow(item, targetGroup)`，导致 `groupLists[index]` 未定义；改为 `forEach((item) => addRow(item))`。
- 归组与保存顺序不一致会产生第二次 PUT：`buildValue` 改为按「归组后的目标位置」排序后解决。
- 测试里在行归组后重新 `panel.querySelector('.bonus-value')` 会拿到另一行的元素，断言前要先保存元素引用。
- `commitBonusValue` 需要同时派发 `input` + `change` + `focusout`（`relatedTarget` 指向行外），否则 jsdom 下不会触发即时保存/归组。
- Edit/Write 后仍要检查行尾（仓库标准 LF）；本次 `git diff --check` 干净。
