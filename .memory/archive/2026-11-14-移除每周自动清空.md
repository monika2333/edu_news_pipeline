## 需求与理由

之前为汇总审阅页做过每周自动清空：Windows 计划任务调用 `scripts/run_clear_review_buckets.ps1`，
脚本再执行 CLI 子命令 `clear-review-buckets`，把**所有管理员**的采纳/备选行置为 `discarded`。
用户长期停用（计划任务已停很久），清空列表用汇总审阅页的「一键清空」（只清当前管理员自己的列表）
和「清理旧新闻」就够了，因此把这条「系统级清空所有管理员」路径整条删除。

**边界**：只删系统级路径；「一键清空」及其后端链路、共用审计动作名
`manual_review.clear_buckets`、「清理旧新闻」全部保留。两条路径在服务层的桶计数逻辑几乎一样、
在 adapter 层也共用审计动作名，删除时已逐处确认没有误伤。

## 注意事项

- 历史数据里 `manual_reviews.decided_by = 'system:scheduled_clear'` 与审计
  `after_data.trigger = 'scheduled'` 的 `manual_review.clear_buckets` 事件是只读存量，
  不清理、不改写。
- `clear-review-buckets`（连字符）在模板 / JS / CSS / 路由里仍大量出现，那是一键清空的 DOM id
  与 API path，与已删除的 CLI 子命令同名但不同物；全仓 grep 校验删除范围时用
  `clear_all_review_buckets` 等下划线符号，不要误删这些。
