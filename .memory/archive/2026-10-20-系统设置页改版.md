# 系统设置页改版（2026-10-20）

## 背景

系统设置页原来是一条 4 个胶囊页签 + 一个大白面板，模型步骤表、数据源三列网格、加分词典、高级长文本框都堆在同一个面板里。用户认为「几个列表放的地方不太合适」，尤其「高级」右对齐小字入口与页签不协调，且计划再增加 1～2 个页签。后续又逐轮反馈：高级关键词的长输入框不方便，数据源「每小时来源」内联账号面板把网格打乱，管理模式需要「先开模式再展开」两层门，最后决定去掉管理模式。

## 最终形态

### 设置页外壳

- 左栏竖向导航 + 右侧内容：`.settings-shell { grid-template-columns: 208px minmax(0, 1fr) }`。
- 导航项 = 短标签 + 副标题（`data-desc` + `::after`，不进无障碍名称）；分组「配置」= 模型/数据源/加分词典，「系统」= 高级。
- `≤1200px` 折叠为顶部等宽页签（与旧顶部版一致的窄屏形态），避免内容区过窄导致步骤表横向滚动。
- 每个分区先渲染页头：`SETTINGS_TAB_META` 维护 `nav` / `title` / `description`；页签只给短标签，不再把标签越写越长。
- 内容按 `.settings-card` 分卡片；模型页顺序为「默认模型与流水线步骤 → 接入点 → 环境」，数据源为「每小时来源 → 每日任务」，加分词典为「关键词加减分 → 排除名单」，高级为四个独立卡片。

### 高级页关键词/别名

- 关键词默认是芯片视图：逐条删除、内联输入回车添加、失焦提交；「批量编辑」展开原生 textarea 做整段粘贴/替换。
- textarea 仍是唯一数据源：`readValue` 只读 textarea，芯片和添加框只是它的视图，输入事件同时触发脏标记、计数、芯片重绘。
- 别名模式：芯片显示「原名称 → 标准名称」，添加入口按 `=`/`＝` 拆分；非法行显示红芯片/红输入。
- 校验失败（空词表、别名缺等号/空侧、自动排序跨类重复）会自动展开对应字段的批量编辑，便于按行号定位。
- 高级页面板高度从 1440px 下约 2712px 降到约 1657px。

### 数据源页

- 每小时来源是**单列列表**：每行「开关 → 来源名 → 账号数徽标 →（展开时）刷新按钮 → 展开/收起」。
- 账号面板是来源行之后的兄弟 `<li>`，**始终渲染、默认 `hidden`**；`state.expandedSource` 存当前展开来源，手风琴同时只开一个；来源启停重渲染后保留展开态。
- **没有页面级管理模式**：展开面板即编辑面。芯片同时是启用开关，并常驻「打开主页」↗ 与「标记删除」×；`＋ 添加账号` 常驻；「刷新账号名称」仅展开时出现在来源行。
- 删除 = 面板内标记 + 本面板确认条：点 × 划掉，面板底部出现「将删除 N 个账号 [取消] [确认删除]」，只提交本来源的标记；404 视为成功；部分失败不回滚已成功的删除，失败标记保留可重试。删除提交中锁全部删除/添加与刷新按钮，`state.deleteSubmitting` 防重复。
- 每日任务只读行去掉了与开关等宽的占位，名称与「每日任务」标题左对齐（实测 x 差 0px）。
- 卡片说明最终为「开关即启停，下一轮抓取按新配置执行」，操作条提示已删除。

## 关键决策与原因

1. **顶部页签 vs 左栏**：两者都做过 demo。左栏更适合未来 5～6 个页签，并让「高级」自然归入「系统」组；代价是内容区窄约 200px，实测 1440px 下内容 968px，步骤表刚好放得下；≤1200px 折叠顶部页签。
2. **芯片 + 批量编辑**：用户认可批量输入的价值，但长文本框不适合日常扫读。textarea 保留为唯一数据源，避免重写校验/保存；芯片负责浏览与逐条操作。
3. **去掉管理模式**：管理模式是全局的，实际任务却是局部的；它还改变芯片语义（启停开关 vs 管理对象），形成「管理模式 → 展开」两层门。最终改为展开即编辑。删除的跨来源批量能力被明确放弃，换取一致性；未来若需要，可加只读的「待删除 N」汇总入口，但不再叫管理模式。
4. **账号面板手风琴**：原三列网格 + 全宽账号面板导致无账号来源单独占 1/3 行、旁边大片空白。单列 + 原位展开保持来源与账号的上下文，同时把卡片高度从 772px 降到约 454px（全折叠）。

## 明确不做 / 不要改回去

- 不恢复顶部页签版作为默认（窄屏折叠形态除外）。
- 不恢复页面级「管理模式」，不把芯片操作藏到第二层模式里。
- 不把高级关键词编辑改回单个长 textarea 作为唯一视图；批量 textarea 必须保留。
- 不恢复每日任务行的开关占位；名称必须与标题左对齐。
- 账号删除的确认条按来源隔离，不做跨来源汇总提交（除非重新拍板）。

## 测试与验证

- `tests/test_settings_page.py` + `tests/test_settings_js_behavior.py`：141 条 jsdom 用例，覆盖芯片删除/内联添加/批量编辑、手风琴展开与重渲染保留、面板内标记/取消/串行删除/404/部分失败、刷新按钮仅展开时可见等。
- 全量 `pytest`：worktree 与 main 均 1467 passed。
- Playwright 截图与 DOM 审计：1440 / 1250 / 1201 / 1200 / 1100 / 900 / 600 / 390 均无横向溢出；侧栏 >1200 生效，窄屏折叠；来源/账号/删除条几何已实测。
- 测试坑：高级页芯片化后 `block.querySelector('input, textarea')` 会命中内联添加框，必须显式用 `.settings-textarea`（已记入 pitfalls）。
