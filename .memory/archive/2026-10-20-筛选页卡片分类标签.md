## 需求与最终形态

单条新闻卡片 meta 行原来有两处字段：

```html
<span class="badge positive">positive</span>
<div class="meta-item">京内: 是</div>
```

合并为一个标签（用户指定样式）：

```html
<div class="meta-item">
    <span class="badge search-category-badge positive">京内正面</span>
</div>
```

- 四种取值：京内正面 / 京内负面 / 京外正面 / 京外负面，样式类沿用 `getSentimentClass`（positive / negative / neutral）。
- 情感非 negative 一律按「正面」（与检索卡片、原文抽屉既有口径一致）；`neutral` 情感显示「京内正面」但样式类是 neutral。
- 地域或情感未就绪（null/undefined/空）时视为未归类：卡片留中性「-」占位，不猜词（旧实现把 null 地域显示成「京外」，属误报，一并修掉）。

## 实现要点

- `manual_filter/utils.js` 新增 `articleCategoryBadge(item)`，作为「京内/京外 × 正面/负面」口径的唯一实现：返回 `{ label, sentimentClass }`，未归类返回 `null`。
- `renderArticleCard` 用它渲染合并标签，删掉 sentiment 原文徽章与「京内: 是/否」两个 meta-item。
- `contentDrawerCategoryBadge`（原文抽屉头部「分类 + 该分类重要性分」）改为在其上叠加分数；`search_drawer.js` 删除自带的 `searchCategoryLabel`，检索卡片改用同一函数。三处（筛选卡片 / 检索卡片 / 两套抽屉）从此共用一份判定，`src/console/AGENTS.md` 的 utils.js 条目同步改写。
- 放弃页卡片、审阅页卡片本来就不展示这两个字段，无需改动；聚类内成员卡片走 `renderArticleCard`，自动生效。
