# 劳动午报（ldwb）人机验证恢复（2026-11-12）

## 现象

`logs/pipeline_ldwb_*.log` 每次都是同一行错误，连续多天 ok=0：

```
[crawl] ERROR ldwb_list: Failed to locate redirect URL for the latest issue.
https://ldwb.workerbj.cn/: Max retries exceeded ... SSLError(... TLSV1_ALERT_INTERNAL_ERROR ...);
http://ldwb.workerbj.cn/: 403 Client Error: Forbidden for url: http://ldwb.workerbj.cn/
```

库里 `raw_articles` 最后一条劳动午报是 2026-09-21 21:45 抓的（2723 条），此后 7 周完全没有新增；
`pipeline_ldwb_*` 日志只保留 ~5 天，所以从日志上看不出断了多久，只能靠库里的 `max(fetched_at)` 判断。

## 根因：站点把「非真人访问」挡在两层验证后面

1. **第一层：工作量证明，算法从 SHA-1 换成了 SHA-256。**
   页面里有 `var zeroLen=4; var stampPrefix="xxxx";`，要求 `sha256(prefix + counter)` 前
   `zeroLen` 位为 0，成功后写 `ctwjcode` / `stampprefix` cookie 并 `location.reload()`。
   适配器还在用 `hashlib.sha1`，算出来的 counter 被站点判无效 → 回 403。
2. **第二层：创天 WAF 的环境指纹页。**
   即使第一层答对，返回的仍是一个「非法访问」页（约 60 KB，含 `g_ctwaf_env_check_info` /
   `g_ctwaf_dyntoken_info`），靠一堆混淆 JS + WebAssembly 采集 `navigator` / canvas / WebGL
   指纹，通过后写 `ctwj_token_*` / `ctw_dnytoken_token_*` / `ctw_dnyclienv_token_*` 三个 cookie
   再 reload。这一层在 Python 侧无法复算。

另外 https 端点一直握手失败（`tlsv1 alert internal error`，站点边缘行为，与证书无关），
正文与刊期页都只在 http 上可用。

## 修复

`src/adapters/http_laodongwubao.py`：

- `_maybe_solve_verification_challenge` 改用 `hashlib.sha256`（第一层正确作答）。
- 新增 `ensure_access(session, timeout, verify, allow_browser)`：先发一次探测请求，正常页面直接
  返回；只有拿到 PoW 页或第二层 WAF 页时才启动一次 headless chromium 换取 token cookie，写回
  同一个 `requests.Session` 后重试。**浏览器只负责过验证，正文抓取仍走 requests**（抓一期 46 篇
  约 13 秒，其中浏览器约 3 秒）。
- 新增 `WafChallengeError`：`_fetch_text` 在 PoW 之后再看到 `stampPrefix` / `g_ctwaf_` 就抛它，
  避免把验证页当正文解析成「founder-content 缺失」这类误导性错误。
- `crawl_latest_issue` 增 `allow_waf_browser` 参数并在最前面调 `ensure_access`。
- 新环境变量 `LDWB_WAF_BROWSER`（默认开，可关掉便于排查站点是否又改了验证）、
  `LDWB_WAF_TIMEOUT`（默认 90 秒），已登记进 `docs/env_reference.md`。

`scripts/tools/backfill_ldwb_issue.py`（补历史工具）同样先 `ensure_access`，并把写死的 https
刊期地址改成 `SITE_BASE`（http），否则工具也是全灭。

## 浏览器侧的两个必须条件

- **必须带 `--disable-blink-features=AutomationControlled` 启动**：裸 `chromium.launch(headless=True)`
  时 `navigator.webdriver === true`，WAF 环境检查直接判 403（实测标题变成 `403 - Forbidden`，
  cookie 只写了一半）。加了这个开关就通过，不需要注入 JS 覆盖 `navigator.webdriver`。
- 等待方式要容忍导航：验证通过后页面会整页 `location.reload()`，轮询 `page.title()` 会撞上
  「Execution context was destroyed」，必须 try/except 后重试；判断成功看 token cookie，不看标题。

## 验证

- 适配器直连：`crawl_latest_issue()` 返回当日（2026-11-12）46 篇，正文合计 3.2 万字符。
- 真实流水线：`python -m scripts.run_pipeline_once --steps crawl --sources ldwb` →
  `ldwb feed rows upserted: 46` / 46 条 detail OK / `result: ok=46 failed=None`，run 状态 success；
  库里 `raw_articles` 的劳动午报从 2723 条涨到 2769 条。
- 计划任务路径：按任务写法 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_ldwb_daily.ps1`
  跑一遍，exit 0、日志落到 `logs/pipeline_ldwb_*.log`，第二次跑正确显示 `existing articles skipped: 46`。
  任务用的是 PATH 上的 `python`（3.13，装了 playwright 1.55 + chromium-1187），不是仓库 `.venv`，
  两边都实测能起浏览器。
- 测试：`tests/adapters/test_http_laodongwubao.py` 9 passed，新增 5 条（SHA-256 前缀零、正常页面
  不启浏览器、WAF 页取 token、关掉浏览器时的报错、浏览器后仍是验证页的报错），并更新了
  `crawl_latest_issue` 的调用序列断言（多了 `ensure_access` 的探测请求）。`ruff check .` 通过。
- 全量 pytest：1943 passed，1 failed —— `test_settings_service.py::test_settings_payload_exposes_endpoints_and_drops_base_url`
  是**预存在**的环境依赖失败（本机 `.env.local` 里的 `OPENROUTER_API_KEY` / `DEEPSEEK_API_KEY`
  会被 `_configured_api_key_envs()` 读进名单），把本次改动 stash 掉同样红，与劳动午报无关。

## 遗留（需用户决定）

- **7 周空档没有补**：库内劳动午报缺 2026-09-22 ~ 2026-11-11。`backfill_ldwb_issue.py --date YYYY-MM-DD`
  现在可用了（`--dry-run` 已验证 46 篇），但要不要补、补多久属于内容决策，见 `open-tasks.md`。
- WAF 是站方随时可改的对抗性设施：再出问题先看日志里是「浏览器握手失败」还是「握手后仍是验证页」，
  两条错误信息是分开的。
