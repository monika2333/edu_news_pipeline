# 账号菜单 z-index 修复（2026-10-08 交付）

> 状态：merge a5e4a20 已推送 origin，worktree/分支已删，用户浏览器验收通过，全量 1397 passed。唯一改动 `header.css` 的 `.account-menu` z-index 20→150 + 3 行约束注释（须压过吸顶工具条最高档 100、低于浮层 1000+）。

## 根因

`.review-toolbar`（sticky，z-index:100）压过 `.account-menu`（z-index:20）；header 无定位故二者在根层叠上下文直接比大小；空列表时工具条自然位置偏高才撞上（退出登录整项不可见不可点）。全站其他 sticky 均 ≤10，冲突仅此一处。

## 留用的验证方法论（纯 CSS 层叠改动，pytest/jsdom 覆盖不到时）

- 静态夹具：把真实 CSS 拷到 %TEMP% 夹具目录 + 手写真实 DOM 结构（头部+菜单、workspace-tab-actions 行、空列表、review-toolbar），`python -m http.server` 起本地服务再用浏览器打开——**浏览器技能的 goto() 不接受 file: URL，必须走 http**。
- **命中检测比截图更硬**：对目标元素按高度 20%/50%/75%/90% 四点跑 `document.elementFromPoint`，修复版应全命中按钮自身；变异版（把**拷贝件**改回旧值，生产文件不动）应命中年长元素 + 截图出现遮挡。
- 几何教训：按钮中心点可能恰好落在覆盖区外（本例工具栏只盖住按钮下沿 40%），多点探测才不会漏报变异。
- 同一夹具可顺带验证浮层序：动态建 `.modal.active` 确认 1000 仍压住菜单 150。
- 验证过的浮层次序：modal/content_drawer 1000 > 账号菜单 150 > sticky 工具条 100；检索抽屉 1050-1200、toast 2000（全表在 pitfalls.md 前端节）。
- 截图红框「-」是「一键清空」首字「一」，菜单盖它属正确行为，勿误判。
