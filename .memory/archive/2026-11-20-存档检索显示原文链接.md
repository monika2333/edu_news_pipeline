# 检索抽屉「报送存档检索」显示条目原文链接（2026-11-20）

## 用户反馈

在检索抽屉的「报送存档检索」里搜出来的重点关注舆情条目，只显示来源「（小红书）」「（微博）」这类字样，不显示它自己的链接；这个链接其实在存档里（存档库详情页的条目 meta 行能看到），理论上检索结果里也应该能显示。

第一版交付后用户觉得链接另起一行「好难看」，指定形态为拼回来源括号内：`（小红书 https://xhslink.cn/o/GGCwbSlHt9）`。

## 根因（纯前端展示遗漏，后端数据齐全）

- 报送文本解析时 `src/domain/submission_archive_parser.py` 的 `_extract_source()` 会把正文末尾来源组 `（来源 链接）` 里的 URL 抠出来存 `submitted_report_items.urls`。本地库现状：重点关注舆情条目 41/41 都有 URL（小红书 41、微信公众号 1；同一章节的北京日报 2 条没有 URL），其他章节基本为空（仅人工编辑过才会补）。
- `src/adapters/db_postgres_submission_archive/_items.py` 的 `search_items()` SELECT 早就带 `i.urls`，`/api/submission-archive/search` 原样透传——**后端不需要任何改动**。
- 只有 `src/console/web_static/js/manual_filter/search_drawer_archive.js` 的 `renderArchiveResults()` 没渲染 `urls`：只渲染标题/正文/来源。
- 对照：存档库详情页 `submission_archive/browser.js` 的 `detailItemMetaHtml()` 早已把 `urls` 渲染成外链，正是用户说「存档里也是有的」的那处。

## 实现

- `search_drawer_archive.js` 新增 `buildArchiveSourceGroup()`：把正文结尾的来源组重建成 `（来源 链接1 链接2）`，来源名沿用 `appendArchiveHighlight` 的关键词高亮，每个 URL 一个 `<a>`（新标签页 + `rel="noopener noreferrer"`），整组是同一个 `.archive-item-source` span；只接受 `^https?://`（解析器与 `PATCH /items/{id}` 编辑接口都按 HTTP(S) 校验，前端再兜一层，避免脏数据把 `javascript:` 塞进 href）；链接文本不做关键词高亮——地址要能整段点击/复制，插 `<mark>` 只会把 URL 拆碎。
- 正文为空但来源/链接存在时也照常渲染来源组（不能把条目自带的链接吞掉）；无 `urls` 时组内只有 `（来源）`，与改动前的 DOM/文案一致（原有 jsdom 断言 `（新京报）` 的用例未改仍绿）。
- `css/modules/search.css`：`.archive-item-source .archive-item-link` 行内样式（主题 `--primary-color`、长链接 `word-break: break-all`），不再有独立的链接行容器。

## 测试

- `tests/js/search_drawer_archive.test.js` 新增 3 条行为用例：管理员/值班双端断言来源组文本为 `（小红书 https://…）`、链接在组内且新标签页打开、来源名仍高亮；多个 urls 按原顺序空格分隔在同一组内；无 urls / 非 HTTP(S) 时保持 `（来源）` 且无链接。
- `tests/test_search_drawer_js_behavior.py` 包装层改为同时渲染 `/duty` 与 `/manual_filter` 页面（共享 drawer 模块改动默认双跑两端），夹具收尾多等一拍再 close（值班页启动链的续发请求，见 `pitfalls.md` 前端节）。
- `tests/test_submission_archive_service.py`：fake adapter 返回带 `urls` 的行，断言 `search_archive()` 原样透传（防止将来有人给响应加字段白名单把 urls 丢掉）。
- `tests/test_db_postgres_submission_archive.py`：检索种子行补 `urls`，真实 DB 断言检索结果带 `urls`（锁 `search_items` 的 SELECT 列）。
- 全量 `pytest`：见 delivery-log；`ruff check .` 通过。

## 维护提醒

- 这类条目的 `link_status` 多为 `unmatched`，没有 `article_id`，打不开内容抽屉，必须走外部链接；不要改成只显示来源名，也不要加「原文」按钮。
- 链接形态是用户拍板的「括号内联」：`（来源 链接）`，**不要另起一行或单独成块**（第一版单独一行被用户否决）。
- `submitted_report_items.urls` 是存档条目的权威字段（见 `docs/data_flow.md` 报送存档节），不要把 URL 写回 `source`/`body` 来「顺便显示」。
- 改动校验/展示口径时记住：`/api/submission-archive/search` 的响应必须继续带回 `urls`，否则前端会静默退化成只剩来源名。
