# 系统性 LLM 错误不计文章失败，推广到 external-filter 与 summarize（2026-11-07）

## 背景

2026-11-06 DeepSeek 接入点事故里，真正危险的不是请求白发，而是同一个系统性错误被摊成每篇文章各自的失败：积压的 241 篇里有 136 篇已记到 2 次，再失败一轮就会被静默「按北京放行」。`cc3598b` / `22b569d` 已在 `geo-classify` 做到「系统性错误不计数、不兜底」，但当时还附带两个用户后来否决的动作：

1. 取消本批剩余请求、停止后续批次；
2. `run()` 末尾重新抛出，让整轮失败、CLI 非零退出。

用户复核后的判断：

- 「不计数、不兜底」必须保留；
- 「提前停止 + 整轮报错」不需要。请求失败本身没有成本，每轮照常请求，接入点恢复后下一轮自动跑通；整轮报错还会让排在后面的 `external-filter`、`submission-dedup` 这一小时都不跑；
- 另外两个步骤有同类风险：`external-filter` 连续失败 3 次会直接标 `external_filtered`（静默淘汰），`summarize` 连续失败 3 次会标 `failed` 且不再被拉取（永久卡住）。

## 设计

### 公共模块 `src/workers/llm_failures.py`

- `is_systematic_llm_error(exc)`：`LLMRequestError.is_systematic`、`LLMQuotaError`、`LLMEndpointKeyMissingError` / `LLMEndpointBlockedError` / `BusinessConfigError`。`llm_chat.py` 的 4xx 分类不动。
- `SystematicErrorAlert(operation=..., worker=...)`：内存标志保证每个 `run()` 最多发一条请求错误告警；额度错误走既有 quota 告警，不占用这个名额；发送异常只打印。跨轮冷却仍由飞书指纹状态文件负责，不依赖跨进程状态做同轮去重（并发失败都在主线程处理）。
- 放在 `src/workers/` 是为了避免 `llm_chat.py` 反向 import `business_config` / `llm_endpoint` 造成循环导入。

### geo-classify

- `_process_beijing_gate`：系统性错误 `continue`，逐篇 `log_error`，不写 `beijing_gate_fail_count`、不调 `complete_beijing_gate`，也不取消剩余 future。
- `_process_gate_backlog`：去掉熔断 `break`；`attempted_article_ids` 已保证同轮不重复请求、循环能结束。
- `GateBatchResult.systematic_error: Optional[Exception]` 改为 `systematic: int`（受影响篇数）。
- `run()`：不再重新抛出；`detail` 的 `systematic` 是本轮受影响篇数，并计入 `log_summary.failed`。

### external-filter

- 系统性错误不调 `mark_external_filter_failure`（否则会 +1 并在上限时标 `external_filtered`），只记日志、告警、计入 `failed`。
- `run()` 增加 `attempted_article_ids` 同轮去重：系统性错误不再涨计数，`fetch_external_filter_candidates` 会反复返回同一批候选；不去重会死循环。去重后每篇最多请求一次、本轮必然结束。

### summarize

- `mark_attempt` 在提交前把 `summary_fail_count` +1（兼作认领）。系统性错误时调新增的 `refund_attempt` 退回这次预加，不调 `mark_failed`，即使 `attempt_count` 已达 `MAX_RETRIES`。
- `refund_summary_attempt` SQL 只对 `summary_status='pending' AND status='pending' AND summary_fail_count > 0` 生效，防止把已完成/已失败/0 计数行改坏。
- 临时错误、单篇超限、普通异常不退回，达上限照旧 `mark_failed`。
- 每轮只 `fetch_pending` 一次，没有同轮重取问题。

### 行为要点

| 场景 | geo-classify | external-filter | summarize |
|---|---|---|---|
| 系统性 / 配置类 / 额度错误 | 不写 fail_count、不兜底、不取消、不 break、run 正常结束 | 不写 fail_count、不淘汰、同轮去重保证结束 | 退回预加计数、不 mark_failed、run 正常结束 |
| 每轮告警 | 最多 1 条请求错误告警 | 同左 | 同左 |
| 临时错误 | 原计数/兜底 | 原计数，达上限 final_failure | 不退回，达上限 mark_failed |
| article 级 4xx | 原计数，达上限保持 pending 死信 | 同临时错误路径 | 同临时错误路径 |
