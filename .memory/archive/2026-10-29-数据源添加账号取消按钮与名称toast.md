# 数据源：添加账号的可见取消按钮与名称解析 toast（2026-10-29）

## 背景

用户反馈两点：

1. 添加账号的输入框「收不起来」——实际上 `buildAccountAddForm` 一直有 Esc 退回，但没有任何可见控件，纯快捷键等于不可发现；
2. 添加头条账号后显示长链接，要手动点「刷新账号名称」才出名称——经排查，**自动解析自 b299cfe（2026-09-20）就存在**（添加成功后前端串行补发单账号 refresh-names，芯片先带「名称解析中」），体感"必须手动"的真实原因几乎肯定是自动解析失败（头条要起 Playwright 无头浏览器，20 秒超时偶发；或控制台机器缺 chromium）而失败提示太隐蔽（小徽章 + 面板错误行），之后手动刷新成功可能是纯重试成功，也可能走通了 `_resolve_account_name_with_fallback` 的存量名称兜底（爬虫已从该账号抓到文章，不再起浏览器）。

## 用户拍板（2026-10-29）

1. 「添加」按钮旁加可见「×」取消（并排，Esc 的等价入口，同一 close）；
2. 添加成功后输入框**不**自动收起，保留连续添加；
3. 名称解析全程 toast 提示。

## 实现（b75a31a）

- `source_accounts.js`：
  - `buildAccountAddForm` 增加 `.account-add-cancel`（×，aria-label=取消添加），点击走与 Esc 相同的 close；
  - `submitAccountAdd` 添加成功 toast 改为「账号已添加，正在获取账号名称…」（未排队解析时仍为「账号已添加」）；
  - `resolveNewAccountName` 成功弹「已获取账号名称：{name}」；失败（HTTP 错误 / 异常 / status=failed）统一弹 `NAME_RESOLVE_FAILED_TOAST`（"账号名称获取失败，可点击「刷新账号名称」重试"），具体原因仍在面板错误行与失败徽章 title。skipped（单账号批次实际到不了）不加 toast，维持静默回「名称待获取」。
- `settings.css`：`.account-add-inline .account-add-cancel` 22px 圆钮，沿用账号芯片操作小圆钮视觉。
- 手动「刷新账号名称」按钮的收尾 toast（`已更新 N 个名称…`）不变，两条路径互不影响。
